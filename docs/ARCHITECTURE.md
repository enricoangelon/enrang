# Enrang Architecture

Implementation blueprint. `SPEC.md` is authoritative for everything a programmer can observe; this document decides how it is built. `DEV_RUNTIME.md` covers the VM, sandbox and hot reload; `TESTING.md` covers `enrang test` and the compiler's own tests.

**Status: M0 is built: the workspace, diagnostics, target tables, test kit and command-line skeleton. Everything from M1 on is design, so no compiler exists yet.** Items marked [measured] were run on the development host on 2026-11-05 (i5-12400F, WSL2, `as` 2.42, rustc 1.97.1); everything else is design knowledge or a target.

**Where things run.** The compiler and `enrang dev` run only on a modern x86-64 development machine and cross-compile. Only their output runs on old chips.

## 0. Load-bearing ideas

1. **R1 makes borrow checking a per-point dataflow.** References live only in frame slots (SPEC 5.1), so a forward `held` map plus backward liveness is a complete checker. No regions, no variance, no drop check.
2. **One MIR, two executors.** Post-mono, post-elaboration MIR is the input to both the VM and the native backend. Any disagreement between them is a bug in one of them, and the VM exists before any x86 does.
3. **Legalise before allocation.** LIR holds only what the target can execute: i64 pairs and soft-float are gone before register handling, and the register allocator never sees a pair.
4. **Location-agnostic emitter.** Any virtual register may live in a register or a stack slot, and fixed scratch registers absorb every spill. This makes the allocator optional, which makes it testable (`--regalloc=none|linear|chaos:<seed>`).
5. **The floor binary is the product.** Default i386 output uses 80386 integer instructions only and runs on every listed CPU. `--cpu` is an optimisation. Every encoder form carries a feature set and `Assembler::emit` refuses anything above the current function's allowed set.
6. **Whole-program, from source, every time.** No object files, no linker invocation, no libc. The embedded library is compiled lazily, so unreferenced code never exists in the output. Tree shaking is a consequence of the mono worklist rather than a separate pass.

### Parallel work rules

- Contract crates (`base`, `hir`, `mir`, `lir`, `target`) change only through their owner. Every other crate has one owner and is the only code in its directory.
- **Text formats decouple the pipeline.** MIR and LIR both have a round-trip text form. A `.mir` fixture is a whole module: declarations, then bodies (section 2.5). `parse_module` builds its own `Tcx` through the public `Tcx::define_adt` and `Tcx::define_fn`, so `enrang-borrowck`, `enrang-vm` and `enrang-codegen` test against `.mir` fixtures, and the emitter against `.lir` fixtures, with no front end. This API lands in `enrang-hir` and `enrang-mir` before M3 work splits. Encoder and writers need nothing from upstream.
- The code registry is generated from SPEC 13.2 at M0 and frozen, so nobody edits a shared error enum. Each code names its phase, owner, milestone and fixture kind, so ownership is never in doubt. Explain pages live in `crates/enrang-diag/explain/EN06.txt`, one file per family.
- Encoder forms live in `crates/enrang-x86/src/forms/<family>.rs`. Library code is split by `lib/` directory. Corpus files are per-feature.
- `#![forbid(unsafe_code)]` in every crate except `enrang-testkit`, whose ptrace stepper is the only `unsafe` Rust in the repository.
- **Determinism.** No `HashMap` iteration in anything affecting output: use `IdVec` or `BTreeMap`. Symbols are ordered by first reach. No timestamps, no absolute paths in output. Two builds of the same input are byte-identical (meta-test, including `TimeDateStamp = 0` on PE). The compiler is single-threaded; only the test runner and the dev watcher use threads.

## 2. Shared contracts

### 2.1 Spans and sources

```rust
pub struct BytePos(pub u32);                  // global offset across all files of a session
#[derive(Copy, Clone, Eq, PartialEq, Hash)]
pub struct Span { pub lo: BytePos, pub hi: BytePos }
impl Span { pub const DUMMY: Span; pub fn to(self, end: Span) -> Span; }

pub struct FileId(pub u32);
pub enum FileOrigin { User, Library, Snippet { outer: Span } }  // compileFails maps back to the outer file
pub struct SourceFile {
    pub id: FileId, pub path: PathBuf, pub text: Arc<str>,
    pub start: BytePos, pub line_starts: Vec<u32>, pub origin: FileOrigin,
}
pub struct Loc { pub file: FileId, pub line: u32, pub col: u32 } // col counts Unicode scalars from 1 (SPEC 2)
pub struct SourceMap { /* files sorted by start */ }
```

Spans are 8 bytes and global, as in rustc. Line and column are computed only when rendering.

- `Span::DUMMY` is `(0, 0)`, and position 0 belongs to no file: the first file starts at `BytePos(1)`, and one position separates consecutive files, so each file's end-of-file position has a single owner, even for empty files. Build spans as `file.start + offset`, never from a bare offset.
- `Span::to` returns the smallest span enclosing both, in either order, and ignores a `DUMMY` argument.
- `line_starts` are relative to the file, and only LF starts a line, so a bare CR is an ordinary scalar. A position inside a character gets that character's column.
- `Symbol`'s `Ord` compares text rather than id, because ids depend on interning order. Section 1's "symbols are ordered by first reach" means linker symbols in output.

The code registry is one macro invocation, with one row per line of SPEC 13.2. It generates `enum Code`, `Code::ALL`, the title table and the data the meta-tests read:

The renderer implements SPEC 13.1 byte for byte: gutter width, annotation line per span with the primary first, `...` gaps, `+`/`~` marks, `= explain`, and the final `error: aborting due to N previous errors`. The G cases of SPEC 14 are its acceptance test. Output is deterministic and colourless unless on a TTY with `--color=auto`.

**Classifying a `for...of` source (SPEC 5.6).** Sema alone classifies, after typing and member lookup, so a getter is a `Call` and never looks like a field. Mirbuild only matches the enum, and borrowck sees only MIR. A loop can therefore not be checked as one shape and built as another, and a test-mode HIR check asserts `is_path_place` on every `Path`. A source whose type, after peeling one reference, is neither `Array` nor `Fixed` is EN1015. The first rule that fits wins:

1. A range from `ForOfSource::Range` is `Range`.
2. Strip one leading `Borrow(m, inner)`. If `inner` is a path, the result is `Path { place: inner, mode: m }`, so `&xs` equals `xs`. If `inner` is any other place, go to rule 6 with `inner` and mode `m`.
3. A path of array type is `Path` in `Shared` mode.
4. A path of reference type is `Path { place: Deref(e) }`, with the mode of the reference.
5. `MoveOp` is `Once` in `Owned` mode. On a reference-typed operand it has already been EN0603.
6. Any other place is `Once` over a borrow of it, `Shared` unless written `&mut`: `Index`, `Static`, a raw `Deref`, a projection from a temporary.
7. A reference-typed rvalue is `Once`, with the mode of its type: a call, a getter, a ternary, `r!`, `&make()`.
8. An owned rvalue is `Once` in `Owned` mode.

Capture analysis treats `Path` as a use of `place` in its mode, because the `Borrow` node is gone.

This contract is frozen before M2, so the sema and mirbuild owners can work in parallel against it. Bodies are generic: `T` stays `Param`. `Copy` is a predicate consulted at MIR building; a `T` not bounded by `Copy` is non-Copy (SPEC 4.10).

### 2.5 MIR

A CFG of three-address statements over places. Generic until mono. No unwinding edges, so a panic is a diverging action inside a statement and never affects the shape of the CFG.

### 2.6 Elaboration, monomorphisation, glue

```text
hir::Body -> mirbuild -> mir(Built) -> borrowck -> elaborate_drops -> mir(Elaborated, generic)
          -> mono worklist -> mir(Mono) -> { enrang-vm predecode | enrang-codegen lower }
```

**Checks run once on generic MIR**, so instantiation cannot add a type or borrow error. Only EN0414 (depth above 64) and EN0435 (`layout_of` on a concrete type, which returns an error and never wraps) depend on an instance. Sealed bounds keep EN0805 and EN0910 out of mono (SPEC 4.10).

**Drop elaboration** runs on generic `Built` MIR using the init dataflow that borrowck already computed. Each `Drop(p)` becomes one of:

| Init state of `p` at the point | Rewrite |
|---|---|
| Definitely uninit | Removed |
| Definitely init, no child moved | `DropGlue(p)` |
| Maybe init | Flag local plus guard; init sites set the flag, moves clear it, including a parent's move clearing its children's flags |
| Partly moved class | Ladder over remaining fields in declaration order, each static or flagged |
| Partly moved enum, nullable or `Result` | `Switch` on the tag first, then a ladder for the active variant only. A flag is meaningful only inside its variant's arm |

The tag switch is what makes `f(null, true)` safe for `function f(o: string | null, c: bool): void { if (o != null && c) { take(o); } }`. `Body.drop_flags` records which flag belongs to which move path. The dev runtime uses that map when rebasing frames (`DEV_RUNTIME.md` section 6).

**Mono worklist.** Roots: `_start` lang item, then `main` or `@entry`, `@panicHandler`, `@globalAllocator` methods, `.boot*` functions and statics, and the test table in test builds. For each `Instance { def, args }`:
1. Clone the elaborated body and substitute.
2. Resolve `T.m(...)` by member lookup on the concrete type (static structural dispatch, SPEC 4.4). Satisfaction has already fixed the member's exact shape, and auto-deref never contributes here.
3. Erase `DropGlue` where `needs_drop(ty)` is false; otherwise point it at a shim instance.
4. Fold `SizeOf`, `AlignOf`, `OffsetOf` and statically decided `CpuHas`.
5. Enqueue callees, every function whose address is taken (`FnAddr`, including inside constants), and referenced statics, recording `(instance, first_reach_span, parent)` for reachability diagnostics.

```rust
pub enum ShimKind {
    DropGlue(Ty), CloneGlue(Ty), EqGlue(Ty), ShowGlue(Ty),  // Eq and Show only in test builds
    FnAsClosure(FnRef),                                     // named function passed as closure: drops the env argument
}
pub struct Instance { pub owner: BodyOwner, pub args: TyList }
pub struct MonoProgram {
    pub target: Arc<TargetSpec>, pub instances: IdVec<InstanceId, Instance>, pub bodies: IdVec<InstanceId, Body>,
    pub statics: IdVec<StaticId, StaticDef>, pub strings: StringTable, pub entry: InstanceId,
    pub layouts: LayoutTable, pub reach: ReachTree,

```

Glue shims are synthesised MIR, so the VM and native code run the same drop logic. User `drop` first, then fields in declaration order; enum switch on tag; array elements by increasing index then the buffer; `Box` inner then block; `string` frees only if `cap > 0` (SPEC 5.7 D2).

**Reachability phase** runs on `ReachTree` after mono: EN0812, EN0809, EN0823, and on VM targets EN1201-EN1205. EN0820 fires, with no `@globalAllocator`, when a reached instance has a local, field, parameter or return of owned `string`, `T[]` or `Box<T>`, a template in an allocating position, or a call into `alloc`. It names the first use in BFS order, and `&string` stays legal because it is `core`.

**EN0824** comes from separate BFS walks, one from each `@interrupt` function, one from the `@panicHandler` and one from the methods of the `@globalAllocator`. A walk fails on reaching the `__rt_alloc` or `__rt_dealloc` lang items (every allocating or freeing library path goes through them, drop glue included) or, from the first two roots, any method of the `@globalAllocator` static. Address-taken functions count as reached, so a `fn` value cannot hide allocation. There is no run-time lock, so the 2 KB allocator budget holds.

**Phase order** (SPEC 13.1), enforced by the driver; each phase reports all its errors and stops the compile at its end:

1. Lexical and syntax.
2. Resolve and types.
3. Moves and borrows.
4. Level and layout: `asm` templates, EN09xx, `@bits`, EN0804 on every MIR `Ref` whose place crosses a `@packed` field with no later `Deref` and whose referent type has alignment above 1 (SPEC 7.6), EN0435.
5. Reachability: root collection (EN0310, EN0809), mono-time EN0414 and EN0435, EN0812, EN0820, EN0823, EN0824, EN1201-EN1205. `check` and compile tests run this phase only if a `main` or `@entry` exists; `build`, `run` and `dev` always do.

User-module bodies are always checked. Library bodies are checked lazily, the first time mono reaches them, and a meta-test checks the whole library per target. A diagnostic in library code is an internal error, exit 3.

On `i386-*` the default float is `soft`, except that `--cpu=sse2` defaults to `sse2`. `--float=soft` is legal on every `i386-*` and VM row and is EN0911 on native `x86_64-*`, which has only `sse2`; `--float=sse2` below level `sse2` is EN0911; `--float=x87` is EN1020; `i386-windows` is EN1031. `--float=sse2` on a VM row is EN0911 too. Any `--cpu` on a VM row, and `x86-64` on `i386-*`, are EN0912. An unknown `--float`, `--format`, `--image` or `--trace` value is EN1304.

**Rule: no compiler code assumes a 64-bit `usize`.** Target sizes are `u64` with `TargetUsize` checks, literals are range-checked against the resolved target (EN0411), and the corpus runs on `vm32` before any i386 backend exists, so a 64-bit assumption in the library or in mono fails at M4.

## 4. Front-end algorithms

**Lexer and parser.** Hand-written, recursive descent with Pratt for SPEC 3.5. Recovery: a missing `;` assumes it at the next line start and folds repeats into the first site's diagnostic, with a count and every insertion in its fix-it; a bad item skips to the next item keyword at brace depth 0; a bad statement skips to `;` or `}`. EN0102 follows the indentation comparison in SPEC 2, so G02 is derived and not guessed. TS habits are recognised at the token (`===`, `var`, `any`) and given EN02xx with recovery as the Enrang form. Expression-context `<` follows SPEC 3.4: it speculates by checkpointing the token index, only with no space before it. `split_token` handles `>>`, `>>>`, `>=`, `>>=`, `**` and `&&` on the parser's request. `parse_array_elem` is the only consumer of `...`: anywhere else the parser reports EN1013 at the token, skips it and goes on, and an `=` after an `ArrayLit` holding a spread reports EN1013 at `dots`, with no EN1010 and no EN0114 (SPEC 3.4). `ParseMode::Build` discards `TestItem` after parsing, so a file with appended tests builds byte-identical to one without. `check` uses `ParseMode::Test` and loads `.test.en` parts, so errors in test items are never skipped.

**Modules.** The loader walks `import`s breadth-first from the entry, mapping `core`, `alloc`, `os` to `enrang-rtlib` (`os` by `TargetSpec.os`). A cycle is EN0304. `foo.test.en` is an extra part of module `foo` in `ParseMode::Test`. The prelude is injected per target layer, and `alloc`'s signatures are in it on every target (SPEC 8.1).

**Resolution** has two passes over items, then body-local scopes. A name resolves to `Res::Local`, `Res::Def`, `Res::PrimType` (for `i32.MAX`) or `Res::Namespace(ModuleId)`, following the binding rule of SPEC 4.12. A namespace is legal only left of `.`. M1's parser accepts `extend` declarations, `enrang-sema` collects them, and `Tcx::member` reads them. "Did you mean" draws on the scope at the error site and on members for EN0303, using Damerau-Levenshtein with threshold `max(1, len/3)`.

**Types.** Bidirectional per body, union-find inference variables with kinds `Any`, `Int`, `Float`. Variables unify across the whole function; defaults apply at the end (index position forces `isize` first). `check_expr(e, expected)` records `Adjust`s at each coercion site from the SPEC 4.5 table and nowhere else; nothing nests. Generic calls follow the three steps of SPEC 4.7: return type, then non-arrow arguments left to right (with `?T` against `&U` pending to the end of the call), then arrows. A member access on an `Any` variable is immediately EN0410. On an `Int` or `Float` variable it looks up `__Int` or `__Float` with `Self` set to that variable. A `where` clause is checked at the call after inference. Float literals stay as text until inference settles their width.

**Array spread** follows SPEC 4.13. `check_array` checks each spread operand with no expected type, records `AutoBorrow(Shared)` on a place, `Reborrow(Shared)` on a `&mut`, and nothing on a `&`, and unifies the element type. The `is_clone` check waits for the end of inference, and its failure is EN0438. A literal with a spread becomes `ArrayBuild`, and the const interpreter never sees one, because `...` in a `ConstExpr` is EN0412 at that token during typing.

**Position checks (R1, R2).** Every field, element, payload and generic argument type must satisfy `is_value_type`; every parameter, local and return type must satisfy `is_slot_type`. Closure types only in parameter position. These checks run on resolved types, so aliases cannot hide a reference.

**Narrowing** is flow state inside `check_expr`, not a post-pass, because it changes types. A `FactSet = BTreeSet<Path>` follows control flow, where `Path` is a local or `this` plus field steps. Facts come from conditions and die per SPEC 4.8. `check_call` checks arguments before committing a receiver's narrowed type, and an assignment checks its right-hand side before its place, so kills run in O6 order, and a fact killed by an argument gives EN0401 with a note.

On loop entry, and for each arrow argument, a prescan of the AST collects assignment targets, `++`/`--`, explicit `&mut path`, `path.m(...)`, `path?.m(...)`, every bare use of a local whose known type is `&mut`, and every binding from a scrutinee or initialiser of that type, including inside nested arrow bodies and spread operands. For `path.m(...)` and `path?.m(...)` it walks declared types from the root local's currently known type, peeling `| null`, `&` and `Box`, and records the access `m`'s receiver mode implies. An unresolved `m` or an unknown type counts as a write of `path` itself. The kill rules apply to everything collected before the loop condition, or before the arrow bodies of that call.

**`check_for_of`** runs in this order:

1. Type the source under the current facts.
2. Classify it (section 2.4).
3. Prescan the body only, so `&mut p` in the source kills nothing and `[...p]` has used its fact already.
4. Apply the kills to every fact except the source facts: those of each `NarrowedPayload(q)` in a `Path`'s `place`.
5. Check the body. Each kill in the flow state keeps its span, and each `continue` and each `break` of this loop, labelled or not, records its state. A `break outer` in an inner loop is a `break` of `outer` and not of the inner loop.
6. Each source fact must be in the state at the fall-through back edge and at every recorded `continue`. A missing one is EN0401 at the source, whose note names the kill. Entry and back edges then all establish the fact.
7. The state after the loop is the join of the head's exit edge with every recorded `break`: the intersection of their `FactSet`s. It is never the head's state alone, because source facts escape the kills of step 4, so a `break` path may have lost one. A read of a lost fact after the loop is EN0303 or EN0401 by its use, and never reaches a `CheckTag` panic.

A move is a kill, so `if (p != null) { for (const x of p) { take(p); } }` is EN0401 in phase 2. With no fact in play, `for (const x of q) { take(q); }` is EN0611 in phase 3.

A narrowed read becomes `NarrowedPayload`, which lowers to `CheckTag` in the run of checks directly before the projection, in the same block, so a narrowing bug panics and cannot read garbage.

**Exhaustiveness.** Maranget usefulness over a pattern matrix, with witnesses for EN0501 and redundancy for EN0503. Constructors on `T | null` are `{Null, Present}`, and lowering to `hir::Pat` wraps any pattern other than `null` and `_` in `Present`.

**Const eval.** A small interpreter over HIR for SPEC 4.9, using checked arithmetic at target widths. Failure or a cycle is EN0412. Top-level `assert` is `ItemKind::StaticAssert`, EN0415 on failure.

**Closures in typeck.** Arrows are typed from the closure parameter's expected type, after all non-arrow arguments. The narrowing prescan runs first; precise per-path captures are computed from the typed arrow body, and they can only be narrower than the prescan's writes.

## 5. MIR construction

- **Evaluation order (O6).** Left to right. Call: receiver value operand, arguments left to right, then the receiver's auto-borrow last, so `a.push(a.length)` needs no two-phase borrow. An explicit `&mut` argument takes effect at its position. Index: value operands, then `CheckBounds`, then the projection, so `a[i] = shrink(&mut a)` computes the address after the call.
- **Reborrows (O7).** Every use of a `&mut T` local lowers to `tmp = &mut *r [reborrow]`, so `const b = a` is `tmp = &mut *a; b = move tmp`. A user-visible `&mut` local is never moved or copied. Only the fresh reborrow temporary is moved, once, into its destination, and the verifier checks that any `Move` of a `&mut` names a `Temp`.
- **Scopes and drops.** A scope stack with one entry per block, plus one temporary scope for each boundary in the D2 table: each condition of `if`, `while`, `do`, `for` and ternary, each `for` step, each right operand of `&&` and `||`, and each full statement. `match` scrutinee and `for...of` source temporaries belong to the whole statement. Each exit (`break`, `continue`, `return`, `?`, fall-through) emits `Drop` and `StorageDead` for every scope crossed, in reverse, with temporaries before the locals of their block (D2).
- **Assignment (D3).** `tmp = v; Drop(x); x = tmp;`.
- **`?`.** `Switch` on the tag; the error arm moves the payload into `_0` as `Err` or `null` and exits through scheduled drops.
- **`match`.** A decision tree from the same pattern matrix as exhaustiveness: `Switch` on the first refutable column, top-to-bottom arm priority, with bindings per the binding mode (SPEC 5.6). Reference-typed or place scrutinee: `Ref [match-binding]`. Rvalue or `move`: moves, and unbound payload fields are dropped on arm entry. A payload that is itself a reference binds as `v = copy (t as Present).0` for `&`, or `v = &mut *(t as Present).0` for `&mut`. An impossible default is `Unreachable`.
- **`for...of`.** Mirbuild only matches `ForSource` (section 2.4). `Path` and every non-owned `Once` lower to one shape, with no special case for `T[N]`, because mono folds `Len` on `Fixed`:

  ```text
  bbP:    { StorageLive(_i); _i = const 0; goto bbH; }
  bbH:    { [CheckTag run]; _n = Len(S); _c = Lt(copy _i, copy _n); switch _c [0: bbX, otherwise: bbB]; }
  bbB:    { StorageLive(x); CheckBounds(copy _i, copy _n); [CheckTag run];
            x = &S[_i] [for-of-element]; _i = Add(copy _i, const 1); goto bbBody; }
  bbBody: ... { StorageDead(x); goto bbH; }
  ```

  - `_i` and `_n` are `isize` locals of kind `HiddenLoop(Index)` and `HiddenLoop(Length)`. `Add` is the wrapping `Binary`, because `_i < _n <= isize.MAX`, and it sits in the bind block, so every back edge, `continue` included, already carries the next index when the safe-point poll runs. `continue` lands on `bbH` after `StorageDead(x)`, and that per-turn reset is why a `const` binding never meets EN0613.
  - `S` is the `Path`'s place. For `Once` it is `*_src`, with `_src` of kind `HiddenLoop(Source)` set before `bbP`: `_src = &place [for-of-hidden]` for a place, `_src = value` for a reference-typed rvalue. The head keeps `_src` live, so its loans last for the whole loop.
  - `CheckBounds` is never elided, even though the head proves it, and the bind is unconditional in `Built` MIR, including for an unused or `_` binding, so the `Ref` still reads `S` for init dataflow. So `function f(arr: D[3]) { for (const d of arr) { consume(arr); } }` is rejected even with `d` unused, and no second turn can move `arr` again.
  - `Ref` and `Len` carry the source expression's span, so EN0608, EN0615, EN0616 and EN0804 point at the source.
  - A `Once` source in `Owned` mode of type `T[]` converts into the `alloc` lang class `ArrayIntoIter<T>` (`HiddenLoop(IntoIter)`), whose `Drop` frees the remainder on `break`, `return` or `?`. Of type `T[N]` it uses the static length, needs Copy `T` and copies each element, otherwise EN1015 (SPEC 5.6). Ranges use a plain counter (`RangeCursor`, `RangeEnd`).
- **Array spread.** `ArrayLit` stays for plain literals, through `AllocArray`. `ArrayBuild` lowers in order. `_out` is a `Temp` of type `T[]`, built empty, with `Drop` scheduled in the statement scope, so a `?` in a later part drops what was built. Each part, left to right:
  - `Item`: evaluate the value, take `_r = &mut _out [auto-borrow]`, call `push`.
  - `Spread(_, Array)`: evaluate `_s` from the operand's adjust (`&src [auto-borrow]`, `&*r [reborrow]`, a copied `&`, or `&tmp [temp-arg]` for a statement temporary), take `_r = &mut _out [auto-borrow]`, call `extendCloned`.
  - `Spread(_, Fixed(N))`: no call can take `&T[N]`, because `T[N]` has no `{ptr,len,cap}` header and `alloc` cannot name it without const generics (EN1014). So it is ordinary MIR, with no `unsafe`, no new statement and no new borrow rule:

    ```text
    _s = &src [auto-borrow]; _k = const 0;
    head: _c = Lt(copy _k, const N); switch _c [0: done, otherwise: body];
    body: CheckBounds(copy _k, const N); _e = &(*_s)[_k] [auto-borrow]; _v = clone(copy _e); _r = &mut _out [auto-borrow];
          push(move _r, move _v); _k = Add(copy _k, const 1); goto head;
    ```

    `_s`, `_k` and `_e` are `Temp`s, so this loop has no `LoopId`, and the dev runtime never replaces it at its back edge.

  Then `_out` moves to the destination. `_out` holds no reference and these calls return `void`, so O9's last clause ends the source's loan when the copy is made. The `Ref` on the source is what makes O11 run: `const r = &mut f; const c = [...f]; r[0] = 1;` is EN0708 and `[...p.arr]` on a packed `u32[4]` is EN0804.
- **Closures.** Capture lowering is by the kind of the captured local. For an owned path: one `env_i = &path` or `&mut path [closure-capture]`. Through a `&mut` local `r`: `env_i = &*r` or `&mut *r [closure-capture]` by use, with a site loan on `*r` held by the env for the call. Only a `&T` local is copied into the env. A closure parameter `f` that is captured: `env_i = &mut f`. Then `env = Aggregate(ClosureEnv, ...)` and `c = ClosureValue { func, env }`, passed as an argument. The arrow body is its own `Body` taking `_env`; captured paths are `*(_env.i)`. Named functions passed as closures get a `FnAsClosure` shim.
- **Forwarding a closure parameter.** Passing `f` as an argument is `tmp = ClosureReborrow(f)`, with a new exclusive loan on `f`.
- **Templates.** Passed directly to `console.log`, `console.error`, `writeTo`, or `panic`: `Display::fmt` calls on a stream `Formatter`, no allocation; for `panic`, the stream is the static panic buffer. Elsewhere: an `alloc` buffer `Formatter`, yielding a `string`.
- **`console.log`.** `hir::Callee::Form(ConsoleLog)` lowers to `console.begin(fd)`, one `fmt` per argument with a space between, and `console.end()`. Arguments are implicit shared borrows, and a packed field is copied to a temporary first. The stack buffer flushes at the end, so one call is one `write`.
- **Intrinsics and host calls.** `Callee::Intrinsic` and `Callee::HostCall` lower directly to the `Intrinsic` and `HostCall` statements; library `@intrinsic` and `@hostCall` declarations are the only way to name them.
- **Test forms.** `expect(a).toBe(b)` lowers to `&a`, `&b`, a call to `EqGlue<T>`, and a cold call to `__fail`, copying a packed field to a temporary first. These are real shared borrows for one statement. `TESTING.md` section 2 covers the rest.

## 6. Borrow checking

Runs per `Body` in the `Built` phase, generically. The checker is exactly SPEC 5.2-5.5; this section makes it implementable. It is deliberately not rustc's NLL: there are no region variables and no constraint graph.

### 6.1 Moves, init, mutability

**Move paths.** A tree over `local(.field | as variant .field)*`, with a node per path that is moved, assigned or dropped. `Box` deref and `[*]` are not move-path steps: an `Operand::Move` whose place crosses a reference deref, raw deref, `*box` or an index reports EN0603, EN0605 or EN0604.

**Dataflow.** Forward `MaybeInit` and `MaybeUninit` over move paths, union at joins.

| State at a use | Report |
|---|---|
| Path or any prefix or child not definitely init, last moved | EN0601, or EN0611 when the move reaches itself around a back edge, or reaches a `for...of` head or bind around one |
| Never assigned | EN0602 |
| Second assignment to a `const` | EN0613 |
| Partial move where a prefix type has `Drop` | EN0607 |
| `this` read before all fields assigned in a constructor | EN0610 |
| `x.f = v` where a proper prefix is not definitely init, other than by moves of its own fields | EN0601 if moved, EN0602 if never assigned. A constructor's `this` is exempt |

To explain a move, `move_sites(path, point)` walks the CFG backward to collect every move reaching the point; the first in source order is labelled, and a second is mentioned when arms differ.

**One report per set of move sites,** as rustc does. `for (const x of q) { take(q); }` reads `q` at the head, at the bind and at `take(q)` itself, and it reports one EN0611: primary the move, labelled `moved here, in an earlier turn`, secondary the source, labelled `read again at the start of the next turn`. `take(q); break;` and `take(q); q = [];` are not errors, and the second one warns (section 6.7).

**Mutability** is one predicate on a place root (SPEC 4.11): EN0608, EN0609, EN0614, EN0615, EN0616, EN0422.

### 6.2 Loans

```rust
pub struct LoanPath { pub root: Local, pub through_ref: bool, pub steps: Vec<Step> }
pub enum Step { Field(FieldIdx), Variant(VariantIdx), Elem /* [*] */, BoxDeref, Capture(u32) }
pub struct Loan { pub path: LoanPath, pub mutable: bool, pub span: Span, pub origin: BorrowOrigin }
pub enum LoanKey { Site(LoanId), Param(u32) }  // Param(i) is a synthetic loan: "the caller's data behind parameter i"
```

Because references exist only in frame slots, a path crosses at most one reference after normalisation, which is why `LoanPath` is flat. Two in-scope shapes need the normal form:

- **Narrowed reference.** `(x as Present).0` followed by a deref normalises to `through_ref` with root `x`, and both steps drop: `(*(x as Present).0).f` with `x: &mut Node | null` becomes root `x`, `through_ref`, `.f`.
- **Inside an arrow.** The root is `_env`, `through_ref` is true, and the steps begin with `Step::Capture(i)`, counted as the one crossing: `*((*_env).i).f` becomes root `_env`, `Capture(i)`, `.f`.

A place crossing a raw pointer deref creates no loan and is never access-checked (SPEC 5.9).

**Slots.** `SlotId` is every local whose type is ref-carrying (`is_slot_type` and not `is_value_type`) plus closure-env and closure-value locals. All other locals hold nothing, which is rule O9's last clause.

**`held`: forward analysis.** Domain `IdVec<SlotId, BitSet<LoanKey>>`, union at joins, reverse-postorder worklist. Entry: `held(p) = {Param(i)}` for each reference parameter.

```text
transfer(stmt):
  d = Ref(mode, p), loan L:
      S = {L}; if p crosses *t: S |= held(t)
      kill(d); held(d) = S minus { loans rooted at d with through_ref }
  d = Use(Copy|Move t), t ref-carrying:        kill(d); held(d) = held(t)    // a moved bare &mut is always a Temp (O7)
  d = Aggregate(present, [t]) / (t as Present).0:  kill(d); held(d) = held(t)
  d = Aggregate(ClosureEnv, ops):              kill(d); held(d) = union of held(ops)
  d = ClosureValue { env }:                    kill(d); held(d) = held(env)
  d = ClosureReborrow(f), new exclusive loan L on f:  kill(d); held(d) = {L} ∪ held(f)
  d = a reference read or reborrowed through _env, loan L on that path:  kill(d); held(d) = held(_env) ∪ {L}
  d = anything else:                           kill(d); held(d) = {}
  d = call f(args) (terminator):
      kill(d); held(d) = if ret is ref-carrying then union(held(args[i]) for i in sources) else {}
      // sources: sig.ret_sources for Callee::Fn; FnPtrSig.ret_sources for Callee::FnPtr

kill(s):  for every slot, remove every loan whose path has root s and through_ref  // old *s is renamed away
          held(s) = {}
```

`kill` is what makes the cursor pattern work. `cur = &mut (*cur).next` builds the new set first, removes loans on the old `*cur` everywhere, and removes its own new loan from the result, because that loan's path names the old `*cur`. The loan on `head` stays held. So a later `const v = &mut (*cur).val; cur2 = &mut (*cur).next` inherits nothing stale, and the SPEC 5.3 cursor pattern is accepted.

**Liveness: backward.** A use is any occurrence of a local as an operand or as the base of a place, including `*r = v`. A definition is a whole-local assignment. `StorageDead` and `Drop` of a reference local are not uses (O10). `V` locals are ignored, since they hold nothing.

**Live loans at point P:** the union of `held_P(s)` over slots `s` live at P.

**Access check.** Each statement performs its reads with liveness before the statement, and its write with liveness after the statement minus the destination. So `x = f(&x)` is accepted when the result holds nothing, and `x = *r` with `r` dead afterwards is accepted. This two-stage rule is the "mid-point" of NLL.

```text
overlap(loan, access_path, access_kind):
  shallow = access_kind in {StorageDead, Drop of a ref local, reassign of a ref local}
  if shallow and loan.path.through_ref and loan.path.root == access_path.root: return false
  return prefix(loan.path, access_path) or prefix(access_path, loan.path)
```

`[*]` matches itself. Different fields are disjoint. `Discriminant(x)` is a read of `x`, so a live `&mut x.(V).0` conflicts with re-matching `x`. Then the O11 table:

| Access | Live shared | Live exclusive |
|---|---|---|
| Read, Copy, shared borrow | ok | EN0708 |
| Write, `&mut` borrow | EN0706 | EN0707 |
| Move | EN0709 | EN0709 |
| Drop, `StorageDead` | EN0711 (EN0712 if the root is a `Temp`) | same |

Calling a closure local is an exclusive use of that local, so a capture or `ClosureReborrow` of it conflicts and reports EN0718. Any other conflict whose loan origin is `ClosureCapture` reports EN0715.

**One report per mistake.** `DiagCtx` dedupes on code and span, which is not enough when one mistake gives two codes, so:

- Conflicts are keyed on (loan, access span). When a `for...of` head's `Len` and its bind `Ref` share a key the `Ref` wins, which gives EN0706, EN0707 or EN0708 by mode, and never a second code. `let keep: &mut i64 | null = null; for (const x of &mut q) { if (c) { keep = x; } } use(keep);` is one EN0707, because `keep` is live at both. With an unconditional `keep = x;` it is one EN0708 at the source: `keep` is overwritten before any read on the path from the bind, so it is dead there. It is live at the head, through the exit to `use(keep)`, so only the head's `Len` conflicts.
- Several loans at one access are tried in `LoanId` order and the first is kept, so a `Once` source reports its `ForOfHidden` loan and not the element's.
- D3's `Drop` has `DropOrigin::Assign` and no access check of its own, since the store right after it reports EN0706 or EN0707. Nothing runs between the two and a `Drop` is no use of a reference, so both see the same live loans. `for (const x of q) { q = []; console.log(x); }` is one EN0706.

### 6.3 R3

**Signature.** `RetSources` is computed once from the signature (`from` clause, else `this`, else all reference parameters, else `NoLoans`), for functions and for `fn` types alike. `from` naming a non-reference is EN0716. A reference return with nothing to borrow from passes the signature check by rule 4; its definition check is what fires, with EN0710 or EN0712.

**Definition check at each `Return`.** For each key in `held(_0)`:

| Key | Result |
|---|---|
| `Param(i)`, `i` permitted | ok |
| `Param(i)`, `i` not permitted | EN0714, with a fix-it adding `from` |
| `Site(L)` with `through_ref` | Ignored: `held` already carries what the reference it crossed holds |
| `Site(L)` on a locally owned path, including by-value parameters | EN0710 |
| `Site(L)` on a `Temp` | EN0712 |

`StorageDead(s)` and `Drop(s)` run before `Return`, so a loan held by `_0` would first surface as EN0711. The checker maps a conflict whose only live holder is `_0` to EN0710 with the borrow site as primary span, and dedupes per loan.

**Call check.** The `Call` transfer above applies the same summary. Checking is modular and signature-stable, which the dev runtime relies on: same signature means same contract.

### 6.4 Closures

The arrow body is checked as its own `Body`, with `_env` a reference parameter. Moving out of `*(_env.i)` is EN0617 by capture origin. A captured reference local cannot be rebound inside the arrow (EN0616), so a closure cannot stash its `&T` argument outside; writes through it are ordinary exclusive captures. The result type is `V`, so nothing leaves. At the creation site, `held(env)` keeps every capture loan alive for exactly as long as the closure temp is live: until the call returns.

**Why captures through `&mut` make a loan.** Copying the local would put no loan on `*r`, and a later reborrow of `*r` in another argument would see no conflict. With the site loan, `both(() => { *r += 1; }, r)` is EN0715 in either argument order.

**Transfer for closure parameters.** A closure value is an exclusive reborrow, so `f` behaves as a `&mut` local that can only be called, captured or forwarded. Each forward takes a loan on `f` for the callee, so `twice(f, f)` conflicts and `visit(f, n); visit(f, m);` does not.

### 6.5 Data for diagnostics

```rust
pub struct BorrowConflict {
    pub code: Code, pub access: Access,          // place, kind, span, method name if via a receiver
    pub loan: LoanId, pub holder: Option<Local>,
    pub later_use: Option<(Local, Span)>,        // the "still in use here" label
    pub at: Point,
}
```

- **`later_use`.** BFS forward from P over the CFG to the first statement using any slot that holds the loan there, preferring user-named slots over hidden ones. G08 labels `job`, with the holder's declaration span as a secondary. The use may be a hidden head read: in `for (const row of grid) { for (const c of row) { grid.push([]); } }` the only later use of `row` is the inner head, labelled `the loop reads `row` again here`.
- **Loan origin selects wording.** `ForOfElement` gives "`queue` cannot change while `job` still points into it"; `ForOfHidden` gives "cannot change while this loop is reading it" and "lasts for the whole loop", for `Once` places; `AutoBorrow` names the method; `ClosureCapture` names the arrow.
- **Fix-its** live in `explain.rs`, keyed by code, and each must compile after application (`{ fixes: true }` tests, which accept warnings in the fixed program). The `[...q]` edit of EN0706 and EN0719 changes `x` from `&T` to `T`, so it is offered only when the mode is `Shared`, `T` satisfies `is_clone`, and the body has no explicit deref of `x`. EN0719 always prints `Help::text` for the index loop, the form with no warning; an index loop does not fix EN0706, so that code never prints it. `job.clone()` is offered only under `is_clone`. The "`archive` only reads `u`" suggestion in G07 queries the callee's MIR for moves and writes of that parameter, when the callee is in user code.

### 6.6 Worked traces

**G11** (`r = &s` in an inner block): `held(r) = {L(s)}` after line 6. `StorageDead(s)` at line 7 is checked; `r` is live because line 8 uses it. `L(s)` is live and shallow does not apply, because `s` is owned. EN0711, with `later_use = line 8`.

**NLL problem case #3** (`getOrInsert`, SPEC 5.3): `hit` holds `{L(*m...), Param(m)}` in the branch that returns it. On the other path `hit` is dead, so the loan is not live and `m.insert(k)` is accepted. There are no regions, so nothing can extend the loan to the other branch.

**G21** (`for (const job of queue) { queue.push("retry"); }`): the bind gives `held(job) = {L(queue[*])}`, and `job` is dead at once, so no slot holding `L` is live at `_t = &mut queue [auto-borrow]`, and the push is accepted. No loan is live at the next head, so `Len(queue)` is accepted too. Section 6.7 then finds that `_t = &mut queue` in a loop block, and warns.

**G08** (the same with `console.log(job)` after the push): `job` is live at the push, so `L(queue[*])` is live there, and `[*]` overlaps `queue`. EN0706, with `later_use = line 7`.

**Complexity.** Slots times loans bitsets per block; functions have few of each. Target under 1 ms for a typical function, and a 1,000-function file in under 300 ms in release [target; rustc checked the same volume in 0.29 s measured].

### 6.7 Warning EN0719

A pass at the end of `borrowck::check`, on `Built` MIR, after all conflict checks of that body. For each `_n = Len(S)` with `_n` of kind `HiddenLoop(Length)`, `S` of type `Array`, and `S`'s root not of a `HiddenLoop` kind:

1. **Loop blocks** are those reachable from the head's continue edge from which the head is reachable. This is the same back-edge test the move rule uses, so `q.push(1); break;` and `q.clear(); return;` do not count, and a conditional push that can return to the head does.
2. **An access counts** if, in a loop block, it is `Ref { mutable: true, place: P }`, an `Assign { dest: P }` or a call with `dest: P`, where `P`'s `LoanPath` has `S`'s root and its steps are a prefix of `S`'s. A whole-local assign to the root counts regardless of `through_ref`, because `overlap` returns false for a rebind of a reference root.
3. **Element `Ref`s and writes** have an `Elem` step beyond `S`, so they do not count, and neither do disjoint fields. So the bind of `for (const x of &mut xs)` does not count.

Auto-borrows, `&mut` arguments, reborrows (`g(q)` lowers to `_t = &mut *q`), `const r = &mut q` in the body and captures all have this one shape, so nested calls need no extra case. A per-body pass cannot see into an arrow, so an exclusive capture counts even if the arrow writes only elements (SPEC 5.6).

**Nothing else can change the source.** Any exclusive loan held across the back edge, such as `const r = &mut q; for (const x of q) { r.push(1); }`, is EN0708 at the head read, so safe code can only change the source through statements inside the loop.

**Emission.** One warning per loop. Primary: the source expression, labelled `read again at the start of every turn`. Secondary: the first counted access in source order. The primary is unique per loop, so nested loops over one source give two warnings and `queue.push(a); queue.push(b);` gives one. Header: `` `queue` can change inside this loop, so the loop may never stop ``.

**Suppression.** A loop is skipped if this body reported a phase 3 error (EN06xx, EN07xx) whose access is in a loop block or at the source span and whose path overlaps `S`. So `const q = [1]; for (const x of q) { q.push(2); }` is EN0614 alone, and an error on `q` outside the loop leaves the warning: `error: aborting due to 1 previous error; 1 warning emitted` (G23).

## 7. Native backend

### 7.1 Pipeline

```text
Mono MIR -> lower + legalise -> LIR -> simplify -> allocate (vreg -> Loc)
  -> emit (Assembler: form + operands) -> relax branches, fixups -> CodeBlob per function
  -> link::Object -> link (order, GC, resolve) -> ELF64 | ELF32 | PE32+ | flat | BIOS image
```

No optimiser beyond: LIR copy propagation and dead-def removal (`--opt=1`, default; `--opt=0` disables), fused compare-and-branch, shortest-form selection, and the allocator. No inliner. `xs[i]` is built inline by the lowering, so the most common small operation needs no call.

### 7.2 LIR

```rust
pub enum VRegClass { G32, G64 /* 64-bit targets only */, X /* SSE2 only */ }
pub enum Val { V(VReg), Imm(i32) }
pub enum Mem {
    Base { base: VReg, index: Option<(VReg, u8)>, disp: i32 }, Slot { slot: SlotId, disp: i32 }, Sym { sym: SymbolRef, disp: i32 },
    Indirect { ptr_slot: SlotId, disp: i32 },   // over-aligned local reached through its hidden pointer slot
}
pub enum Inst {
    Mov { dst: VReg, src: Val, w: Width }, MovImm64 { dst: VReg, imm: u64 },
    Load { dst: VReg, mem: Mem, w: Width, sign: bool, volatile: bool },
    Store { mem: Mem, src: Val, w: Width, volatile: bool }, Lea { dst: VReg, mem: Mem },
    Alu { op: AluOp, dst: VReg, a: Val, b: Val, w: Width },
    AluPair { op: PairOp, dst: (VReg, VReg), a: (Val, Val), b: (Val, Val) },   // add/adc, sub/sbb; i386 only
    Checked { op: CheckOp, dst: VReg, a: Val, b: Val, w: Width, signed: bool, site: PanicSite },
    CheckedPair { op: PairOp, dst: (VReg, VReg), a: (Val, Val), b: (Val, Val), signed: bool, site: PanicSite },
    Bounds { index: Val, len: Val, site: PanicSite },
    SetCc { cc: Cond, dst: VReg, a: Val, b: Val, w: Width },
    CmpBranch { cc: Cond, a: Val, b: Val, w: Width, then_: BlockId, else_: BlockId },
    CmpPairBranch { cc: Cond, a: (Val, Val), b: (Val, Val), then_: BlockId, else_: BlockId },
    MulWide { lo: VReg, hi: VReg, a: Val, b: Val }, DivRem { op: DivOp, dst: VReg, a: Val, b: Val, w: Width, signed: bool },
    Shift { op: ShiftOp, dst: VReg, a: Val, count: Val, w: Width }, ShiftPair { op: ShiftOp, dst: (VReg, VReg), a: (Val, Val), count: Val },
    Fp { op: FpOp, dst: VReg, a: VReg, b: Val, w: FpWidth }, FpCmpSet { .. }, FpCmpBranch { .. }, FpConvert { .. },
    Call { target: CallTarget, args: Vec<ArgLoc>, rets: Vec<VReg> }, CallForeign { .. },
    Asm(Box<LirAsm>), MemCopy { dst: Mem, src: Mem, bytes: u32 }, MemSet { dst: Mem, value: u8, bytes: u32 },
    MemCopyDyn { dst: Val, src: Val, bytes: Val, overlap: bool }, MemSetDyn { dst: Val, value: Val, bytes: Val },
    DivWide { q: VReg, r: VReg, hi: Val, lo: Val, d: Val },   // div r32; only from the DivWideU32 intrinsic
    Jmp(BlockId), Ret(Vec<Val>), Unreachable,
}
```

**Key invariant: flags never live across an LIR instruction.** `AluPair` emits `add` and `adc` (or `sub` and `sbb`) as one unit with only `mov` between them, because `mov` preserves flags and `xor r, r` does not, so the emitter never uses the zero idiom inside a pair. `Checked` contains its own `jo` or `jc`. Spill code therefore cannot break a carry or an overflow check. Checked by `lir::verify` and by the chaos allocator.

**Values.** Never-borrowed scalars are vregs. Aggregates and address-taken scalars live in frame slots with explicit size and alignment. Narrow values (`i8`, `i16`) have undefined upper bits and use native 8- and 16-bit forms, except for multiply and divide, which widen (section 7.8). `MemCopy` carries a `u32`; a constant size above `2^31`, which a heap element type can reach on `x86_64`, uses `MemCopyDyn`.

### 7.3 Legalisation

| MIR | `x86_64` | `i386` soft | `i386` `sse2` |
|---|---|---|---|
| `i64` add, sub | `Alu` G64 | `AluPair` | `AluPair` |
| Checked `i64` add, sub | `Checked` | `CheckedPair`, OF or CF of the top word | same |
| `i64` mul | `imul` with `jo`; `mul` for `u64` | `__mulo64`, `__umulo64` | same |
| `i64` div, rem | `idiv`/`div` with checks | zero and `MIN / -1` inline, then `__sdiv64`, `__udiv64`, `__srem64`, `__urem64` | same |
| `i64` compare | `cmp` | `CmpPairBranch`: high word, then low word | same |
| `i64` shift | `Shift` | `ShiftPair`: `shld`/`shrd` plus a branch for counts of 32 or more | same |
| `f32`, `f64` move | `movss`, `movsd`, X vreg | G32 vregs | X vreg |
| Float add, sub, mul, div, sqrt | `Fp` | `__addf64` and friends | `Fp` |
| Float `%` | `__remf64` | same | same |
| Float compare | `ucomisd` | `__cmpf64` | `ucomisd` |
| Float to int, after the range and NaN check | `i8` to `i32`, `u8`, `u16`: `cvttsd2si r32`. `u32`, `i64`: `cvttsd2si r64`. `u64`: `cvttsd2si r64` if `x < 2^63`, otherwise `cvttsd2si(x - 2^63)` xor `1 << 63` | `__f64toi32` and friends | `i8`, `i16`, `i32`, `u8`, `u16`: `cvttsd2si r32`. `u32`, `i64`, `u64`: helpers |
| Int to float | `cvtsi2sd`; `u64` by shift-and-sticky | helper | `cvtsi2sd` for `i32`, helper otherwise |
| `toBits`, `fromBits` | `movq` plus canonical check | integer moves | `movd`, `movq` via slot |

`cvttsd2si` returns the indefinite value `0x8000000000000000` for `1.0e19` as `r64` [measured], which is why `u64` needs the second path and why `u32` needs `r64` or a helper. GenExpr and GenFloat force edges at `2^31`, `2^32`, `2^63`, `2^64` and one ulp below each, on every cell.

### 7.4 Register strategy

Each vreg gets one location for its whole lifetime, with no splitting.

| Role | i386 | x86-64 |
|---|---|---|
| Fixed | `esp`, `ebp` | `rsp`, `rbp` |
| Scratch, never allocated | `eax`, `ecx`, `edx` | `rax`, `rcx`, `rdx`, `r10`, `r11` |
| Allocatable, callee-saved | `ebx`, `esi`, `edi` | `rbx`, `r12`-`r15` |
| Allocatable, caller-saved | none | `rsi`, `rdi`, `r8`, `r9` |
| XMM allocatable | `xmm0`-`xmm5` | `xmm0`-`xmm13` |
| XMM scratch | `xmm6`, `xmm7` | `xmm14`, `xmm15` |

The scratch set is exactly what `mul`, `div` and shifts need, so fixed-register constraints vanish. All XMM registers are caller-saved in the internal convention. Byte operations on `esi` or `edi` route through a scratch register, since only `eax`-`ebx` have byte forms on i386. `rsi` and `rdi` have them with REX.

**Allocators.**
- `none`: every vreg in a slot. Exercises every memory-operand path.
- `linear`: linear scan without holes or splitting. Each physical register has blocked positions (calls for caller-saved, `MemCopy` for `rsi`, `rdi`, `Asm` for its clobbers and bindings). An interval overlapping a blocked position cannot use that register. Move hints prefer the incoming register. On pressure, spill the interval with the furthest end.
- `chaos:<seed>`: random legal locations. The corpus must match across all three.

**Parallel moves** at calls and function entry use the standard cycle resolver with one scratch register.

### 7.5 Frames

Frame pointers are always on: they give stack traces and stable slot addressing.

```text
i386:    [ebp+8...] args   [ebp+4] return   [ebp] saved ebp   [ebp-4...] saved ebx/esi/edi (used only)
         slots below that; esp free, so argument pushes are natural
x86-64:  [rbp+16...] stack args  [rbp+8] return  [rbp] saved rbp  saved callee-saved  slots  outgoing area at [rsp]
```

- **i386 prologue:** `push ebp; mov ebp, esp; sub esp, N`. Epilogue: restore, `leave`, `ret args`.
- **Alignment:** i386 keeps 4 (no aligned-SSE assumption anywhere); x86-64 keeps 16 at every call. A local whose alignment exceeds that gets a hidden pointer slot, because `ebp` mod A is unknown and `esp` moves with argument pushes. The prologue does `mov eax, esp; sub eax, size; and eax, -A; mov esp, eax; mov [ebp-k], eax`, LIR reaches the local through `Mem::Indirect`, and `esp` is restored through `ebp`. Stack-limit and probe checks use `size + A - 1`.
- **Stack probes:** frames of 4 KB or more on hosted targets, not only Windows, because safe recursion must not jump a guard page. Probes run before the frame is used and addresses descend from the current stack pointer, at most one page per step: for `off = 0x1000, 0x2000, ...` while `off < N`: `test eax, [rsp-off]`; then `sub rsp, N`. An ascending probe's first touch is the deepest page, past the guard. On Windows 10.0.26300 with commit 0x1000 and reserve 8 MiB, a first touch at `rsp-0x8000` and an ascending probe over 64 KB both exit `0xC0000005`, and a descending probe over 256 KB succeeds [measured]. Linux grows the stack on any touch within the rlimit, so `lx64` cannot show this: the `win64` cell runs a corpus program with a 1 MiB local, and an LIR golden pins the probe order.
- **Freestanding limit check** on by default. Small frames: `cmp esp, [__stack_limit]; jb stub`. Frames of 256 bytes or more use a form that cannot wrap: `mov eax, esp; sub eax, N; jb stub; cmp eax, [__stack_limit]; jb stub; mov esp, eax`. So `let a: u8[131072]` on a 16 KB stack at base `0x10000` reports `stack overflow` instead of wrapping through address 0.
- **`__stack_limit`** is a writable `.data` word. Start sets it to stack bottom plus a fixed reserve: 2 KB under `soft`, 3 KB under `sse2`. The reserve covers the hardware frame, stub pushes, the 512-byte `fxsave` with its alignment, and panic printing. Island panic functions compile without the check, and the overflow stub writes 0 to `__stack_limit` before anything else, so the panic path cannot re-enter it. Float values in panic messages use a fixed work area in `.bss` under the panic guard flag, so printing fits the reserve. A bench test runs every panic message at the limit and fails if stack use passes the reserve. `unsafe cpu.setStackLimit(addr)` updates the word for a kernel that switches stacks, adding the reserve. Disabling the check (`--no-stack-limit`) forfeits soundness on overflow, and the option's help says so.
- **`DF` is clear** at every call boundary; the `asm` contract requires restoring it.
- **`MemCopy`:** small constant sizes as inline `mov`s through scratch; larger as `rep movsd` then `rep movsb`, with the allocator treating `rsi`, `rdi` as clobbered on x86-64 and the emitter wrapping `esi`, `edi` in push/pop on i386. Slots are `ebp`-relative, so the pushes are safe. `MemCopyDyn` and `MemSetDyn` take run-time sizes and emit the same string forms; with `overlap` they add a backward path that sets and then restores DF.
- **Padding:** `int3` between functions (never executed). No loop alignment at the floor, because multi-byte NOP is forbidden and `0x90` runs would slow loops for no benefit.

### 7.6 Calling conventions

Internal, unstable, one per architecture, independent of OS.

| | i386 | x86-64 |
|---|---|---|
| Int args | Stack, pushed right to left | `rdi rsi rdx rcx r8 r9`, then stack |
| Float args | Stack words (all strategies) | `xmm0`-`xmm7`, then stack |
| Returns | `eax`; `edx:eax` for `i64`, `f64`; `eax` for `f32` | `rax`; `xmm0` |
| Cleanup | Callee (`ret n`), saving bytes per call | Caller, fixed outgoing area |
| Callee-saved | `ebx esi edi ebp` | `rbx rbp r12-r15` |
| Closure value | Two words: code, env | Two registers or stack words: code, env |
| Closure call | Env pushed as hidden first argument | Env in `rdi`, shifting the rest; code through scratch |

The i386 float ABI is identical under all strategies, so a float strategy never changes the calling convention. **Aggregates** pass by pointer to caller-owned memory, and the callee owns the contents after a move, including the right to write them. So a Copy-typed source is copied to a temporary, and that temporary is elided only when all of these hold: the operand is rooted at an owned local with no `Deref` and no static; no live loan overlaps it (not merely no later direct use); the local is not address-taken; and this is its last use. Everything else copies. Otherwise `bump(r.big)` would write through a `&T`, `bump(K)` would write `.rodata`, and `bump(h.big)` would change what a live `q = &h` sees. Each case has a VM-against-native differential fixture. Returns go through a hidden first pointer.

**Return slot aliasing.** `x = f(x)` or `x = f(&x)` must not write directly into `x`. The destination is elided only when it is a fresh, unborrowed local that the arguments do not mention; otherwise a temporary is used.

**Foreign calls** take scalars, raw pointers and `fn` pointers only (EN0816). Struct-by-value is EN1030, so neither SysV classification nor Win64 by-reference rules exist.

- **Win64:** `rcx rdx r8 r9`, positional `xmm0-3`, 32 bytes of shadow space, 16-byte alignment, stack args from `[rsp+32]`. The internal callee-saved set is a subset of both platform ABIs, so `CallForeign` needs no extra saves.
- **`@abi("win64")` entry functions** (UEFI entry, callbacks) additionally save `rsi`, `rdi` and `xmm6-15`.
- **Windows imports** call `FF 15 rel32` through the IAT slot [measured with hand-written PE]. `cdecl` and `stdcall` are parsed and report EN1030, so 32-bit Windows is not precluded.

**Process entry.**

| Target | `_start` | Exit |
|---|---|---|
| `x86_64-linux` | `xor ebp, ebp; mov rdi, rsp; and rsp, -16; call __rt_start` (entry `rsp` is 0 mod 16 [measured]) | `exit_group` #231 |
| `i386-linux` | `xor ebp, ebp; mov eax, esp; push eax; call __rt_start` | `exit` #1 |
| `x86_64-windows` | `xor ebp, ebp; and rsp, -16; sub rsp, 32; call __rt_start` (entry `rsp` is 8 mod 16 [measured]) | `ExitProcess` |
| `i386-none` | Section 9.6 | `halt` |

`__rt_start` runs the level check, sets up the panic state, calls `main`, and maps its result: `void` to 0, `i32` to that code, `Result` `Err` to `error: <e>` on stderr and 1.

### 7.7 Value representation

- **Layout** is exactly SPEC 11: fields in declaration order, no reordering, no niche. `T | null` is tag + payload; `&T | null` is `2P`. Enums have a `u32` tag at 0.
- **Zero-sized types** occupy slots of size 0. Arrays of them never allocate and have `cap` equal to the maximum `usize`, and growing one past `len == isize.MAX` panics with `capacity overflow`, so `Len` always fits `isize` and `i386` stops at 2^31 elements. `Box` of one is a dangling aligned pointer with no allocation.
- **Sum types.** `Switch` lowers to a compare chain for up to 4 arms and a balanced binary search otherwise. No jump tables, so code needs no absolute data relocations and no indirect branches. Payload projections are plain offsets; `CheckTag` is `cmp` plus a cold branch to the `unexpected null` or internal-tag panic.
- **Strings.** `{ptr, len, cap}`. A literal's bytes are in `.rodata`. In `&string` position it is a pointer to a `{ptr, len, 0}` descriptor in `.rodata`, holding no loan and needing a `.reloc` on PE. In `string` position its three words are stored into the slot. `+` calls `__str_concat(&a, &b)`; `+=` copies first if `cap == 0`.
- **Arrays.** `{ptr, len, cap}`. Indexing is `cmp idx, len; jae stub` (the unsigned compare also catches negative `isize`), then a scaled address. Growth doubles with minimum capacity 4, and `cap * size <= isize.MAX` is checked on every target (`capacity overflow`, reachable on i386, where IA32 emulation gives a process nearly 4 GiB).
- **Drops.** `DropGlue(p)` calls `drop_glue<T>(p)`, by internal convention, or disappears when `needs_drop` is false.
- **`T[N]`.** Inline; `RepeatLit` is `MemSet` for byte-identical patterns, otherwise a loop.

### 7.8 Checks, panics, stack traces

A failed check branches to a per-site cold stub at the end of the function:

```text
stub:  push len ; push idx ; call __panic_bounds   // i386, 5 bytes plus operand moves
       (idx, len) -> (rdi, rsi) ; call __panic_bounds     // x86-64, through the parallel-move resolver
```

The x86-64 moves go through the resolver because `rsi` and `rdi` are allocatable: with `idx` in `rsi` and `len` in `rdi`, naive moves would report `len` for both. An LIR fixture pins that case. The return address is the location key, resolved through `.enr.trace`.

| Check | Sequence |
|---|---|
| Signed or unsigned overflow | `add`/`sub` then `jo` or `jc`; never `inc`/`dec` because they leave CF unchanged |
| Multiply | 32- and 64-bit: two-operand `imul` with `jo`; unsigned `mul` with `jo`. `i8`, `u8`, `i16`, `u16`: widen to 32 bits in scratch with `movsx` or `movzx`, `imul r32`, then range-compare against the narrow type. `imul al, bl` does not exist [measured] |
| Divide | Explicit zero and `MIN / -1` tests at every width, because hardware raises #DE. `i8`, `u8`, `i16`, `u16`: widen to 32 bits the same way and use `idiv r32` or `div r32`, so 8-bit `div` with its AH remainder is never generated |
| Shift | Range check first, because hardware masks the count |
| `as` int to int | Range compare against target bounds |
| Float to int | Range and NaN test first, because `cvttsd2si` returns indefinite on overflow; lowering per section 7.3 |

**Trace table (`.enr.trace`, read-only):**

```text
header  u32 magic "ENRT", u32 fn_count, u32 site_bytes, u32 file_count, u32 string_bytes
fns     fn_count x { u32 start_off_from_text, u32 name_off }        // sorted by start
sites   per function: ULEB128 site_count, then (ULEB pc_delta, SLEB line_delta, ULEB col, ULEB file_idx)
files   file_count x u32 name_off
strings NUL-terminated names
```

`--trace=full` keeps everything; `fn` keeps names and only the panicking site's line and column; `none` drops the section, so messages have no location or stack. The walker follows `ebp`/`rbp`, checks alignment, monotonic increase and stack bounds, and stops at 0 or after 64 frames. `_start` zeroes the frame pointer; interrupt stubs build a synthetic frame. A guard flag sends a second panic straight to exit or halt. Output format is SPEC 9.1 exactly.

### 7.9 `i64` on i386

- Two independent `G32` vregs; address-taken ones are 8-byte slots with alignment 4.
- Helpers are `@lang` functions in `core/int64.en`: `__mulo64`, `__umulo64`, `__sdiv64`, `__udiv64`, `__srem64`, `__urem64`, plus decimal formatting that splits by 10^9.
- **Division traps:** `div r32` raises #DE unless EDX is below the divisor. The helper fast-paths `hi == 0`, uses two `DivWideU32` steps for 32-bit divisors, and uses shift-subtract otherwise. `DivWideU32(hi, lo, d)` has the precondition `hi < d`, lowers to `div r32` (LIR `DivWide`), and is precondition-checked in the VM, so the helper runs in `vm32` and under `--float=soft` with no `asm`.
- **No self-recursion.** Helpers use only `u32` arithmetic plus the `MulWideU32` and `DivWideU32` intrinsics and inline `AluPair`. A meta-test walks the call graph: no compiler-inserted helper may reach itself, whether through soft-float, `i64` operations or panics.
- `Atomic64` needs `i586`; volatile `u64` is EN0805 because it would tear.

### 7.10 Floats

**Decision: `soft` and `sse2` are in the prototype. x87 is deferred past M10 with soft-float as the universal fallback.** It adds no correctness, the Q8400 has SSE2, and every extra strategy adds a bit-exactness burden. `--float=x87` is EN1020. The slot stays in `FloatStrategy`. SPEC 9.3 fixes the recipe x87 must follow and the bit vectors it must pass before it can ship.

| Strategy | Where | Implementation |
|---|---|---|
| `soft` | Default on `i386-*` | `core/softfloat/`: IEEE 754 binary32 and binary64 in integer-only Enrang. Add, sub, mul, div, rem, sqrt, compare, conversions. Round to nearest-even only, full subnormals, no traps |
| `sse2` | Default and only on `x86_64-*`; `i386-*` at level `sse2` | Scalar forms only: `addss/sd`, `subss/sd`, `mulss/sd`, `divss/sd`, `sqrtss/sd`, `ucomiss/sd`, `cvt*`, `movss/sd`, `movd/q`. No m128 operand, so no alignment fault is possible on a 4-aligned i386 stack |
| Host | VM | Rust `f32`/`f64`, or `--float=soft` to interpret the library |
| `x87` | Deferred | EN1020. Probing forms only (`fninit`, `fnstsw`, `fnstcw`, `fnsave`, `frstor`, `fwait`), tagged `fpu` |

**Bit-exact guarantee.** SPEC 9.3 states it; the mechanics are:
- `%` is always the `core` function (exact, like `fmod`), on every strategy. SSE2 has no such instruction.
- Negation and `abs` are bit operations through a general register (`movq rax, xmm0; btc rax, 63; movq xmm0, rax`). `0 - x` is wrong for `+0`, and `xorpd m128` needs an aligned constant.
- `floor`, `ceil`, `trunc`, `round` are `core` code because `roundsd` is SSE4.1.
- MXCSR stays at `0x1F80` (no FTZ, no DAZ, all masked). Freestanding startup loads it; hosted OSes provide it.
- `toBits` canonicalises NaN with one compare. No per-operation cost anywhere.
- Soft-float matches SSE2 NaN bits as an internal test, stronger than the language guarantee.
- Float printing (Dragon4, integer-only, stack bignum) and parsing (bignum) are the same code on every strategy.

### 7.11 Atomics

Threads are deferred, so atomics serve interrupt-versus-mainline sharing (SPEC 10.5). All lower to intrinsics:

| Operation | Level | Lowering |
|---|---|---|
| `load`, `store` | all | `mov` of exact width |
| `exchange` | all | `xchg` (implicit lock) |
| `add sub and or xor` | all | `lock` ALU, no result |
| `incAndTestZero`, `decAndTestZero` | all | `lock inc/dec`, ZF |
| `testAndSet`, `testAndClear` | all, on `u16 u32 usize i32`; `bts` has no byte form [measured] | `lock bts/btr`, CF |
| `fence` | all | `lock or dword ptr [esp], 0` |
| `compareExchange`, `fetchAdd` | `i486`+, else EN0910 | `lock cmpxchg`, `lock xadd` |
| `Atomic64` | `i586`+, else EN0910 in phase 4 | `lock cmpxchg8b` (memory operand only) on i386, 64-bit forms on x86-64. `@align(8)` on every target, so it never splits a cache line |

`AtomicValue` and `AtomicBits` are sealed bounds in `core`, so `T` is never a surprise at mono. There is no silent emulation of CAS. In the VM all are plain operations, since it is single-threaded and has no interrupts. `cpu.withoutInterrupts` is `pushfd; cli; ...; popfd`, freestanding and uniprocessor only.

### 7.12 Encoder

One table and one pure function. Forms are declared per family:

```rust
form!(ADD,  [RM32, R32],  op(0x01),        modrm_r,      modes(M16|M32|M64), I386);
form!(ADD,  [RM32, IMM8S], op(0x83),       modrm_digit(0), modes(M16|M32|M64), I386);
form!(CMOV, [R32, RM32],  op0f(0x40+cc),   modrm_r,      modes(M16|M32|M64), CMOV);
form!(ADDSD,[XMM, XMM_M64], pf2_op0f(0x58), modrm_r,     modes(M32|M64),     SSE2);
```

Fields: mnemonic, operand kinds, opcode map and bytes, mandatory prefix, ModRM kind (`/r`, `/digit`, `+r`, none), immediate kind, operand-size attribute, REX.W, valid modes, required `FeatureSet`. About 800 forms in total.

**Byte order:** segment override, address-size `67`, operand-size `66`, `rep`/`lock`, then mandatory `66`/`F2`/`F3`, then REX, then opcode. A mandatory prefix placed after REX voids the REX. This matches GAS's order [measured in `.code16`: `addr32 rep movsd` is `67 66 F3 A5`; `mov byte ptr es:[ebx], 1` is `26 67 C6 03 01`; `lock add dword ptr fs:[eax], 1` is `64 67 66 F0 83 00 01`].

**Mode rules:**
- **16-bit** (boot subset only): the M16 form list is generated from what `lib/boot` assembles, and a meta-test requires the list to equal that set. It includes `mov`, `mov sreg`, ALU, `test`, `lea`, `xchg`, shifts, `mul`, `div`, `push`, `pop`, `call`, `ret`, `int`, `in`/`out`, branches, `cli`, `sti`, `cld`, `hlt`, `lgdt`, `lidt`, far `jmp`, `mov cr0`, string ops, `pushf`/`popf`, `pushfd`/`popfd` and `cpuid`. `66` selects 32-bit operands, `67` selects 32-bit addressing, with its own BX/SI/DI/BP ModRM table. `data32 ljmp 0x08, 0x1000` is `66 EA 00 10 00 00 08 00`; `data32 lgdt [m]` is `66 0F 01 16 ...` [measured].
- **32-bit:** an ESP base requires SIB; an EBP base with no displacement requires disp8.
- **64-bit:** R12 behaves like RSP and R13 like RBP. `mod=00 rm=101` is RIP-relative, and absolute addressing needs SIB. The RIP displacement is measured from the instruction end including trailing immediates [measured: `add dword ptr [rip+0x20], 5` is `83 05 20 00 00 00 05`], so `RipRel32` relocations carry that delta. SIL and DIL need an empty REX; AH to BH cannot coexist with any REX.

**Selection** picks the shortest legal form (`83 /0 ib`, accumulator short forms, `inc r32` outside 64-bit mode). On ties it uses the direction GAS chooses, so the oracle compares bytes directly. Branches start short and only grow, to a fixed point. The exception is an allowed set lacking `Ia32` (section 7.14), where a `Jcc` that cannot stay short is a build error. On an 8086 the long form's `0F` decodes as `pop cs`; GAS at `.arch i8086` emits `73 03 E9 ...` where `i386` emits `0F 82 ...` [measured].

### 7.13 Inline assembler

About 700 lines over the same table. Intel syntax, one instruction per line or `;`, local labels `name:` scoped to one `asm`, per SPEC 7.4.

- **Directives in `@naked` bodies**, user and library: `db`, `dw`, `dd`, `dq`, `align`, and `times <n> db <v>` with `$` and `$$`, so a raw boot sector is user code (SPEC 7.5).
- **Library-only addition** for boot and startup code: symbol operands (`call __rt_start`, `lea eax, [sym]`) resolving against same-module functions and lang items. In user code a symbol operand is EN0903.
- **Operand binding.** `in` and `out` bind places to named physical registers, so there is no allocator interplay: the LIR `Asm` instruction blocks those registers and the clobbers at its position, and saves any callee-saved ones through the prologue. Bind moves go through the parallel-move resolver. Out places count as initialised for init dataflow. Flags and memory are assumed clobbered.
- **Diagnostics:** EN0901 (level), EN0902 (unknown mnemonic with did-you-mean), EN0903 (operands), EN0904 (register), EN0905 (`esp`, `ebp`, `rsp`, `rbp`), EN0915 (interpolation), EN0916 (MMX, 3DNow!, packed SSE), EN0917 (register not valid in this mode), EN0914 (`popa` warning; a `nop` is inserted after it at `i386`).
- **`@naked`, `@bits`.** Body is one `asm` statement, no prologue. `@bits(16)` assembles in `Mode::M16`, and calling such a function is EN0913.

### 7.14 Level enforcement

```rust
define_features! {
    Fpu "fpu", Cpuid "cpuid", Bswap "bswap", Cmpxchg "cmpxchg", Xadd "xadd", Cmpxchg8b "cmpxchg8b",
    Rdtsc "rdtsc", Msr "msr", Cr4 "cr4", Cmov "cmov", Fcomi "fcomi", Mmx "mmx", Amd3dnow "3dnow",
    Sse "sse", Sse2 "sse2", Sse3 "sse3", Ssse3 "ssse3", Sse41 "sse4.1", Sse42 "sse4.2", Popcnt "popcnt",
    Fxsave "fxsave", Nopl "nopl", Pae "pae", Nx "nx", Lm "lm", Invlpg "invlpg",
    Ud2 "ud2",      // internal tag, P6 and up; not queryable through cpu.has
    Ia32 "ia32",    // internal tag on every form outside the 8086 subset; not queryable through cpu.has
}
```

Levels are bitsets because the ISA is not a line: K6 has MMX and lacks CMOV, while Pentium Pro has CMOV and lacks MMX [measured with `as`]. Every level has `Ia32`. Stage 1 assembles with an allowed set lacking it, which is what keeps its pre-386 check honest; the `i8086` oracle checks the same thing independently (`TESTING.md` section 15.2). Scalar SSE1 forms and `ldmxcsr`/`stmxcsr` are tagged `sse`, which level `sse2` includes.

**Per-function allowed set.** `allowed = TargetSpec.allowed ∪ @requires(...)`, or `floor ∪ @requires(...)` inside the floor island (section 8.4). `Assembler::new(mode, allowed)` checks every emit with `form.features ⊆ allowed`:

- Generated code above the level is an internal compiler error, exit 3.
- Inline assembly above the level is EN0901, naming the instruction, its feature, the lowest level providing it, and the current level. Every `asm` in a user module is checked in phase 4, reachable or not; library `asm` is checked when reached, and all of it by a per-target meta-test.

Enforcement is verified independently of the tags: assembler oracle per form, disassembly audit of whole output, single-step classification at run time (`TESTING.md` section 15).

### 7.15 Interrupt stubs

The compiler emits for `@interrupt` (SPEC 7.7): `cld`, individual `push`es and `pop`s (never `pusha`/`popa`), a synthetic frame for stack traces, then the body, then `iretd` or `iretq`. Under `sse2`, the state around the body is saved by aligning the stack (`mov ebp, esp; and esp, -16; sub esp, 512; fxsave [esp]`). Under `soft` there is nothing to save.

`idt.set` checks that vectors 8, 10-14 and 17 pair with `errorCode` handlers. The PIC is remapped to `0x20`/`0x28` with I/O delays before `sti`. `idt.enable()` also clears the NMI mask with `out 0x70, 0x0D` then `in 0x71`, because stage 2 masked it. x86-64 uses the 16-byte IDT and always `fxsave`s. No target uses a red zone, so interrupts on the current stack are always safe, and the `__stack_limit` reserve covers the hardware frame, stub pushes and `fxsave`.

### 7.16 Traps, collected

- `setcc` needs a byte register, then `movzx`.
- 64-bit ALU immediates are sign-extended imm32; anything else goes through a scratch register.
- SSE enablement on freestanding: after detection, clear CR0.EM, set CR0.MP, set CR4.OSFXSR and OSXMMEXCPT, `fninit`, `ldmxcsr` default, all before any float use. CR4 is touched only when CPUID reports a CR4 feature, because the 386 has no CR4.
- Flat output has no loader, so startup zeroes BSS using `__bss_start` and `__bss_end`.
- PE `.reloc` is required for absolute data pointers (string descriptors, static `fn` tables) because of `DYNAMIC_BASE`.
- Size arithmetic (`cap * elemSize`) must be checked: it is reachable on i386.
- 386 POPA erratum: never emitted by the compiler; the inline assembler warns and inserts a `nop`.

### 8.2 The `--cpu` ladder

SPEC 10.1 fixes the rungs. Implementation: each rung is one table entry plus a small number of codegen predicates.

| Level | `FeatureSet` | Codegen uses | Startup check (floor code) |
|---|---|---|---|
| `i386` | `ia32` | Base forms | None hosted; stage 1 rejects 8086/286 |
| `i486` | + `bswap cmpxchg xadd invlpg` | `bswap` in `swapBytes`; `lock cmpxchg`, `lock xadd` | AC toggle |
| `i586` | + `cpuid cmpxchg8b rdtsc msr cr4` | `Atomic64` | ID toggle, TSC and CX8 bits |
| `i686` | + `cmov fcomi ud2` | `cmov` in integer `min`, `max` | CMOV bit |
| `sse2` | + `sse sse2 fxsave` | Float strategy `sse2`; `fxsave` in interrupt stubs | SSE2 and FXSR bits; freestanding sets CR4.OSFXSR |
| `x86-64` | `ia32 cpuid cmpxchg8b cmpxchg xadd bswap rdtsc msr cmov fcomi fpu ud2 sse sse2 fxsave nopl lm invlpg cr4 pae` | Baseline; **not** CMPXCHG16B, long-mode LAHF/SAHF, POPCNT, SSE3+. `generic64` accepts `ud2`, `fninit` and `fcomi` [measured] | None hosted; LM bit freestanding |

Aliases per SPEC 10.1 are resolved in `enrang-target` and print a note. `native` is rejected (EN0909): the host is never the target. `core2` is deliberately not a rung, because a non-vectorising compiler gets nothing from SSSE3. MMX, 3DNow! and SSE1 are never rungs; K7 stays at `i686` because SSE without SSE2 cannot do `f64`.

### 8.3 Startup detection

Runs in floor code, before any higher instruction:

```text
detect486:  pushfd; pop eax; mov ecx, eax; xor eax, 0x40000; push eax; popfd     // AC, bit 18
            pushfd; pop eax; push ecx; popfd; xor eax, ecx; test eax, 0x40000    // nonzero: 486+
detectCpuid: same with 0x200000                                                  // ID, bit 21; nonzero: CPUID exists
cpuid(0): max leaf, vendor
cpuid(1): EDX FPU 0, TSC 4, MSR 5, PAE 6, CX8 8, CMOV 15, MMX 23, FXSR 24, SSE 25, SSE2 26
          ECX SSE3 0, SSSE3 9, SSE4.1 19, SSE4.2 20, POPCNT 23
cpuid(0x80000000): EAX is the maximum extended leaf; every extended bit reads 0 unless EAX >= 0x80000001
cpuid(0x80000001): EDX NX 20, LM 29, 3DNow 31
```

The extended-leaf guard is required: the SDM says an out-of-range leaf returns the highest basic leaf's data, so without it a P5 or P6 can show a false LM, NX or 3DNow bit.

CPUID has no bit for some `cpu.has` names. The `checkLevel` table defines them:

| Feature | Defined as |
|---|---|
| `bswap`, `cmpxchg`, `xadd`, `invlpg` | AC toggle |
| `fcomi` | FPU and CMOV bits |
| `cr4` | Any of VME, DE, PSE, TSC, PAE, MCE, PGE in CPUID.1:EDX |
| `nopl` | LM bit only, matching our level table |

`checkLevel(flags)` is one table-driven function, also tested with fake flags. A failure prints `needs i686 (CMOV); this CPU lacks it`. Linux exits 126, Windows calls `ExitProcess(126)`, and freestanding writes VGA and COM1, then halts.

**FPU probe, freestanding only** (SPEC 10.3): clear CR0.EM and TS, seed a word with `0xA5A5`, `fninit`, `fnstsw` into it, expect 0; `fnstcw`, expect `0x037F`. On CPUs without CPUID, also require CR0.ET = 1, because a 287 beside a 386 passes the probe but has ET clear; it counts as no FPU.

**FPU and SSE state.** With `--float=soft` below level `sse2`, startup sets CR0.EM=1, so any stray x87 opcode traps to `#NM` and panics: a run-time proof that no x87 code executes. At level `sse2` and above, whatever the float strategy, startup leaves CR0.EM=0, CR0.MP=1, CR4.OSFXSR=1 and CR4.OSXMMEXCPT=1, so `cpu.has("sse2")` can fold to `true` honestly. Below that level `unsafe cpu.enableSse()` does the same and refreshes the cache.

`cpu.has` caches a detected bitset on first use; a feature within the static level folds to `true` at mono. On freestanding targets the cached `fpu`, `sse*` and `fxsave` bits mean usable now: the CPUID bit, CR0.EM clear, and for SSE CR4.OSFXSR set. CR4 is read only when `cr4` is true.

### 8.4 The floor island

Startup, the level check and panic printing are compiled at `floor` whatever `--cpu` says (SPEC 10.4). No marks are needed: the island is computed as the call-graph closure from `_start` and from the `__panic_*` entry points, cut at two boundaries: the call to `main` or `@entry`, and the call to `@panicHandler`, which sit at target level because the level check has passed by then. Shared callees (`core/fmt`, Dragon4) compile once at the floor. On `x86_64-*` the floor is `x86-64` itself.

**Floats in the island.** Inside the island, floats legalise as in the `i386` soft column of section 7.3 whatever the strategy: G32 words, and `toBits` as integer moves. The i386 float ABI is already stack words, so callers interoperate. Without this, `--cpu=sse2 --float=sse2` would put SSE2 in code that runs before the level check. An `Fp` LIR instruction in an island function is an internal error.

A meta-test verifies the island from assembler records and asserts it contains no `Fp` instruction, and the audit disassembles island symbols at `-march=i386`. The only exceptions are the FPU probe forms, which audit at `i386+387`.

### 8.6 What "supported" means, per family

Four classes (SPEC 10.6), generated from test results by `enrang targets --evidence`:

- **C3 emulated,** naming the model.
- **C4 real hardware,** only from the owner's report.

**A floor binary hits no ISA obstacle on any listed chip.** The limits are environmental:

- **`i386-linux`** needs a kernel with `int 0x80`. Linux 7.1 removes the 486 build options per April 2026 reports, and 386 support ended in 2012. So on real 386 and 486 machines it needs an old kernel, and it uses only old syscalls. Here it runs through IA32 emulation [measured].
- **`i386-none`** needs legacy BIOS or CSM. It is the real route to the oldest chips.
- **UEFI-only machines** need `x86_64-none --format=efi`.
- **Windows:** only `x86_64-windows`. 32-bit Windows is EN1031: not requested, not built, not precluded.

## 9. Output writers

### 9.1 Link model

```rust
pub struct Object { pub sections: Vec<Section>, pub symbols: IdVec<SymId, SymbolDef>, pub entry: SymId, pub imports: Vec<Import> }
pub enum SectionKind { Boot, Text, Rodata, Trace, Data, Bss, Custom { flags: SectionFlags } }
pub struct Section { pub name: Symbol, pub kind: SectionKind, pub align: u32, pub bytes: Vec<u8>, pub bss_size: u64,
                     pub relocs: Vec<Reloc>, pub fixed_addr: Option<u64> }
pub enum RelocKind { Abs32, Abs64, Rel32, RipRel32 { trailing: u8 }, ImportRip32 }
pub struct Reloc { pub offset: u32, pub kind: RelocKind, pub sym: SymId, pub addend: i64 }
pub struct LinkedImage {
    pub segments: Vec<Segment>, pub entry: u64, pub base: u64, pub symbols: Vec<(String, u64)>,
    pub absolute_fixups: Vec<u64>,                 // addresses of pointer-sized absolute data, for PE .reloc
    pub imports: ImportTable, pub bss: (u64, u64),
}
```

**Order (SPEC 7.8):** `.boot*`, `.text*`, `.rodata*`, `.enr.trace`, `.data*`, `.bss*`, then custom sections in first-use order. Text is one blob per function in first-reach order, starting with `_start`. Linker GC drops unreferenced statics and strings; functions are already tree-shaken. `@at` storage takes an address and no bytes; overlap is EN0813.

**Linker symbols:** `__text_start`, `__rodata_start`, `__trace_start`, `__trace_end`, `__data_start`, `__bss_start`, `__bss_end`, `__image_end`, `__stack_bottom`, `__stack_top`. `.bss.stack` holds the stack and is reserved for the compiler. `__stack_limit` is not a linker symbol: it is a `.data` word that start computes from `__stack_bottom` (section 7.5).

A relocation that does not fit its field, and an image span above `2^31 - 1` on a RIP-relative target, are EN0435 and never truncate.

### 9.2 ELF64 (`x86_64-linux`, ET_EXEC)

Ehdr, 64 bytes:

| Off | Size | Field | Value |
|---:|---:|---|---|
| 0 | 16 | `e_ident` | `7F 45 4C 46 02 01 01 00`, 8 zero bytes |
| 16 | 2 | `e_type` | 2 |
| 18 | 2 | `e_machine` | `0x3E` |
| 20 | 4 | `e_version` | 1 |
| 24 | 8 | `e_entry` | `_start` |
| 32 | 8 | `e_phoff` | 64 |
| 40 | 8 | `e_shoff` | 0, or section table with `--symbols` |
| 48 | 4 | `e_flags` | 0 |
| 52 | 2 | `e_ehsize` | 64 |
| 54 | 2 | `e_phentsize` | 56 |
| 56 | 2 | `e_phnum` | 4, or 3 with no RW segment |
| 58 | 2 | `e_shentsize` | 64 |
| 60 | 2 | `e_shnum` | 0 unless `--symbols` |
| 62 | 2 | `e_shstrndx` | 0 unless `--symbols` |

Phdr, 56 bytes, field order: `p_type u32, p_flags u32, p_offset u64, p_vaddr u64, p_paddr u64, p_filesz u64, p_memsz u64, p_align u64`.

| # | Type | Flags | Contents |
|---|---|---|---|
| 0 | `PT_LOAD` (1) | R X (5) | Headers, `.boot*`, `.text*` |
| 1 | `PT_LOAD` | R (4) | `.rodata*`, `.enr.trace` |
| 2 | `PT_LOAD` | R W (6) | `.data*`, `.bss*` via `p_memsz > p_filesz`; omitted if empty |
| 3 | `PT_GNU_STACK` (`0x6474E551`) | R W | Omitting it can give an executable stack |

**Size discipline.** No file padding between segments: `p_offset ≡ p_vaddr (mod 0x1000)` holds by bumping the vaddr of the next segment by one page, as `ld -z noseparate-code` does. The boundary file page is mapped twice with different permissions. This is what makes a 12 KB hello reachable, and a hand-built ELF64 of this shape ran here at 4,136 bytes [measured]. `--symbols` appends `.symtab`, `.strtab`, `.shstrtab` and section headers, so `objdump` and `readelf -s` work.

### 9.3 ELF32 (`i386-linux`, ET_EXEC)

Ehdr, 52 bytes: `e_ident` as above with class 1 at byte 4; `e_type u16` 2; `e_machine u16` 3; `e_version u32` 1; `e_entry u32`; `e_phoff u32` 52; `e_shoff u32`; `e_flags u32` 0; `e_ehsize u16` 52; `e_phentsize u16` 32; `e_phnum u16`; `e_shentsize u16` 40; `e_shnum u16`; `e_shstrndx u16`.

Phdr, 32 bytes, **different order**: `p_type, p_offset, p_vaddr, p_paddr, p_filesz, p_memsz, p_flags, p_align`, all `u32`.

Same segment plan and size discipline, base `0x08048000`. Old kernels ignore `PT_GNU_STACK`. A hand-built ELF32 using old `mmap` #90, `write` and `exit` through `int 0x80` ran here at 4,214 bytes [measured].

### 9.4 PE32+ (`x86_64-windows`, EFI)

```text
0x000  DOS header: "MZ", zeros, e_lfanew at 0x3C = 0x40
0x040  "PE\0\0"
0x044  COFF header, 20 bytes
0x058  Optional header PE32+, 240 bytes
0x148  Section table, 40 bytes each
       Headers padded to FileAlignment
```

COFF: `Machine u16 0x8664; NumberOfSections u16; TimeDateStamp u32 0; PointerToSymbolTable u32 0; NumberOfSymbols u32 0; SizeOfOptionalHeader u16 240; Characteristics u16 0x22`.

| Opt off | Field | Value |
|---:|---|---|
| 0 | `Magic` | `0x20B` |
| 2 | Linker version | 0, 0 |
| 4, 8, 12 | `SizeOfCode`, `SizeOfInitializedData`, `SizeOfUninitializedData` | From sections |
| 16 | `AddressOfEntryPoint` | `_start` RVA |
| 20 | `BaseOfCode` | `.text` RVA |
| 24 | `ImageBase` u64 | `0x140000000`; `0x100000` for EFI, which firmware relocates through the mandatory `.reloc` |
| 32, 36 | `SectionAlignment`, `FileAlignment` | `0x1000`, `0x200` |
| 40 | OS, image, subsystem versions | 6.0, 0.0, 6.0 |
| 52 | `Win32VersionValue` | 0 |
| 56, 60 | `SizeOfImage`, `SizeOfHeaders` | Computed |
| 64 | `CheckSum` | 0 |
| 68 | `Subsystem` | 3 CUI; 10 EFI application |
| 70 | `DllCharacteristics` | `0x8160` (`HIGH_ENTROPY_VA`, `DYNAMIC_BASE`, `NX_COMPAT`, `TERMINAL_SERVER_AWARE`); 0 for EFI |
| 72, 80 | Stack reserve, commit | `--stack-size` (default 8 MiB; EFI keeps the freestanding default of 16 KiB), `0x1000` |
| 88, 96 | Heap reserve, commit | 0, 0 (`VirtualAlloc` only) |
| 104 | `LoaderFlags` | 0 |
| 108 | `NumberOfRvaAndSizes` | 16 |
| 112 | Data directories, 8 bytes each | Index 1 Import, 5 BaseReloc, 12 IAT; rest 0 |

Sections, each 40 bytes (`Name[8], VirtualSize, VirtualAddress, SizeOfRawData, PointerToRawData, PointerToRelocations 0, PointerToLinenumbers 0, NumberOfRelocations u16 0, NumberOfLinenumbers u16 0, Characteristics`):

| Name | Characteristics | Contents |
|---|---|---|
| `.text` | `0x60000020` | Code |
| `.rdata` | `0x40000040` | `.rodata*`, `.enr.trace` |
| `.data` | `0xC0000040` | `.data*`, `.bss*` (`VirtualSize > SizeOfRawData`) |
| `.idata` | `0xC0000040` | Import tables |
| `.reloc` | `0x42000040` | Base relocations |

**Empty sections.** The writer omits every section with zero virtual and raw size and zeroes its data directory, keeping sections contiguous and rounding `SizeOfImage` to `SectionAlignment`. This is required: a `.data` section with `VirtualSize` 0 and `SizeOfRawData` 0 is refused by the loader, `VirtualSize` 16 with raw size 0 runs, and a `DYNAMIC_BASE` image with no `.reloc` runs [all measured through interop]. For `--format=efi`, `.reloc` is mandatory, so with no fixups the writer emits one block of an 8-byte header plus two type-0 entries.

**Imports.** Descriptors are 20 bytes each, null-terminated: `OriginalFirstThunk` (ILT RVA), `TimeDateStamp` 0, `ForwarderChain` 0, `Name` RVA, `FirstThunk` (IAT RVA). ILT and IAT entries are `u64` RVAs of hint/name records, zero-terminated. Hint/name: `u16` hint 0, ASCII name, NUL, pad to even. Only referenced imports appear. A meta-test asserts the only DLL is `kernel32.dll`.

**`.reloc`.** Blocks of `PageRVA u32, BlockSize u32, entries u16` with type 10 (`DIR64`) in the top 4 bits and page offset below, padded with type 0 to a 4-byte boundary. Generated from `LinkedImage.absolute_fixups`. Code is RIP-relative. No `.pdata`: foreign unwinders cannot walk our frames, which is acceptable with no callbacks. A hand-built PE32+ of this shape ran from the Linux filesystem through WSL interop at 1,536 bytes [measured].

**Windows layer imports:** `GetStdHandle`, `WriteFile`, `ReadFile`, `CreateFileW`, `CloseHandle`, `GetFileSizeEx`, `DeleteFileW`, `GetCommandLineW`, `GetEnvironmentVariableW`, `GetSystemTimeAsFileTime`, `Sleep`, `VirtualAlloc`, `VirtualFree`, `ExitProcess`, `GetLastError`, `GetConsoleMode`, `WriteConsoleW`. `CommandLineToArgvW` lives in `shell32`, so `os/windows` parses the command line itself. Paths convert between UTF-8 and UTF-16. `console.log` writes exact bytes (`\n`, no CRLF) to pipes and files through `WriteFile`, so corpus output compares equal. When `GetConsoleMode` succeeds the handle is a console: output converts from UTF-8 to UTF-16 in a stack buffer, split at code point boundaries, and goes through `WriteConsoleW`. Nothing global changes, so the user's shell keeps its code page, unlike `SetConsoleOutputCP`, which outlives the process.

### 9.5 Flat

Exact bytes from the lowest section address to the end of `.data`, with gaps zero-filled. `.bss` is excluded. There is no loader. `--base=<addr>` sets the link base; first byte is `_start`, unless user `.boot*` sections exist, in which case their first function is the raw entry, `@entry` is optional, and with no `@entry` no startup code is emitted. Default base is `0x10000` on `i386-none` and `0x100000` on `x86_64-none`.

**`--multiboot` is deferred past M10** (EN1041), to pay for `enrang-sema`.

### 9.6 BIOS images

`enrang build --target=i386-none --image=floppy|hdd`. No BIOS boot code has been executed here, because no emulator is installed; this section is design knowledge until the bench and QEMU tests run. The two images are separate rather than a hybrid, because BIOSes guess the type from the first sector and may patch a BPB in floppy emulation.

**LBA 0 (stage 1, 512 bytes):**

| Bytes | Floppy | Hard disk |
|---|---|---|
| 0-2 | `EB 58 90` (jump to 0x5A) | `31 C0 EB` |
| 3 | First byte of OEM | `56` (`xor ax, ax; jmp short` to 0x5A) |
| 4-10 | Rest of OEM `ENRANG  ` | Zero |
| 11-61 | 1.44 MB BPB: 512 B/sector, 1 sec/cluster, 1 reserved, 2 FATs, 224 root, 2880 sectors, media `F0`, 9 sec/FAT, 18 spt, 2 heads. Scratch: never read | Zero, so nothing resembles a BPB |
| 62-89 | Zero | Zero |
| 90-439 | Stage 1 code, at most 350 bytes | Same |
| 440-443 | Signature `ENRG` | Same |
| 444-445 | Zero | Zero |
| 446-509 | Zero | One entry, then three zero entries |
| 510-511 | `55 AA` | `55 AA` |

Partition entry on hard disk images: `80 | CHS start | 7F | CHS end | u32 LBA 2048 | u32 sectors`. Type `0x7F` is reserved for development, and one active partition is present because some BIOSes refuse USB sticks without one [S, anecdotal]. CHS uses 255 heads, 63 sectors: LBA 2048 is `20 21 00`, clamped to `FE FF FF` above cylinder 1023.

**Image geometry:**

| | Stage 1 | Stage 2 | Kernel | Total |
|---|---|---|---|---|
| Floppy | LBA 0 | LBA 1-8 | From LBA 16 | Exactly 1,474,560 bytes; kernel at most 1,466,368, else EN1304 |
| Hard disk | LBA 0 | LBA 1-8 (gap after MBR) | From LBA 2048, in the partition | 1 MiB plus kernel, rounded to 512 |

Stage 2 fits track 0 on any PC disk, so reaching it needs no geometry beyond what stage 1 already handles.

**Stage 1 (`lib/boot/stage1.en`, `@bits(16)`, 8086-compatible throughout):**

Assembled with an allowed set lacking `Ia32` (section 7.14), so nothing above the 8086 subset can appear before the pre-386 check.

1. `cli`, far jump to normalise CS to `0000:7Cxx`, zero DS, ES, SS, stack at `0x7C00`, `sti`, `cld`, save DL. Interrupts stay on through all BIOS calls, because some BIOS timeouts rely on IRQ0 ticks; `cli` is used only around the 8042 and protected-mode sequences.
2. Reject 8086 and 286 (SPEC 10.1): `pushf`/`popf` test of FLAGS bits 12-15, stuck set on 8086, stuck clear on 286 in real mode. Print `C` through INT 10h AH=0Eh and halt.
3. Disk probe. Extensions are present only when `AH=41h` gives CF=0, BX=0xAA55 and CX bit 0 set. Geometry: zero ES:DI, then `AH=08h`; it is valid only when CF=0 and `(CL & 0x3F) != 0`. If invalid, use 18/2 for DL below 0x80. A hard disk with neither extensions nor valid geometry prints `D`. So no path can divide by zero in LBA-to-CHS.
4. `readSector(lba, seg:off)`: exactly one sector per call, three retries with `AH=00h` resets, reloading all registers before each call. With extensions it uses `AH=42h` with a packet, and falls back to `AH=02h` CHS after those retries fail, if geometry is valid. It prints `D` only when both fail. Slow on floppy and acceptable: 16 KB takes seconds.
5. Load 8 sectors from LBA 1 to `0x7E00`.
6. Jump to `0000:7E00` with DL = drive, SI = address of `readSector`.

**Stage 2 (`lib/boot/stage2_*.en`, at most 4,096 bytes, loaded at `0x7E00`):**

Bytes 0-1 `jmp short`, bytes 2-3 version, then patched parameters:

```text
offset 4:  u32 kernel_lba      u32 kernel_sectors   u32 kernel_base
offset 16: u32 kernel_entry    u32 kernel_bytes     u32 bss_end       u32 flags (bit 0: long mode)
```

One GDT serves every image, and long-mode images add the last entry:

| Selector | Use | Bytes |
|---|---|---|
| `0x00` | null | zeros |
| `0x08` | code32 | `FF FF 00 00 00 9A CF 00` |
| `0x10` | data32 | `FF FF 00 00 00 92 CF 00` |
| `0x18` | code16 | `FF FF 00 00 00 9A 00 00` |
| `0x20` | data16 | `FF FF 00 00 00 92 00 00` |
| `0x28` | code64, long-mode images only | `FF FF 00 00 00 9A AF 00` |

The steps:

0. **Long-mode check,** on long-mode images only, first and in real mode so `L` can print. ID toggle with `pushfd`/`popfd`, then `cpuid(0x80000000)`, the extended-leaf guard of section 8.3, then the LM bit. Failure prints `L` through INT 10h and halts, before anything is loaded. A 386 fails at the ID toggle with no `cpuid` executed. This function, and the tail of section 9.7, are `@requires(...)`, so the rest of stage 2 stays at the floor.
1. **Memory.** E820, then E801, then `AH=88h`, plus INT 12h. Never write-probe. 386-era BIOSes likely offer only `AH=88h`, and SX tops out at 16 MB [M].
2. **Devices.** COM1 base from BDA `0x400`; CRTC base from BDA `0x463` (`0x3B4` means mono at `0xB0000`, otherwise `0xB8000`). INT 10h AH=0Fh; if the mode is not 2, 3 or 7, set AX=0003h. Columns from BDA `0x44A`; rows are 25, except from BDA `0x484` on EGA and later. Store in `BootInfo`.
3. **A20.** Test wraparound (`0000:0FF0` against `FFFF:1000`, which aliases it with the gate closed and lies outside `BootInfo`; byte saved and restored). Then, in order: `AX=2401h`; 8042 with bounded polling (`D1`, `DF`, then `out 0x64, 0xFF`, the null command UHCI legacy emulation needs), with IF=0 during the sequence; port `0x92` last, read-modify-write, bit 0 never set, skipped if it reads `0xFF`. After each method, poll the wrap test in a bounded loop of at least 65,000 iterations with an `out 0x80` delay between them before trying the next, because an old 8042 can take milliseconds. Failure prints `A`.
4. `data32 lgdt`, once.
5. **Kernel.** Compare `bss_end` with the INT 12h top for low bases and with the detected extended size for high bases; failure prints `M`. If `kernel_base == 0x10000`: read directly, one sector at a time. Otherwise: read 64 KB chunks into the bounce buffer at `0x10000`, and copy each with the toggle below. This avoids unreal mode, whose survival across BIOS calls is not guaranteed.
6. Stop the floppy motor if DL is below 0x80 (`out 0x3F2, 0x0C`). `cli`, mask both PICs, NMI off (`out 0x70` bit 7).
7. Set CR0.PE by read-modify-write, then immediately `66 EA off32 0008`.
8. In 32-bit mode: load segments with `0x10`, ESP `0x7C00`, clear EFLAGS, EBX = `0x500`, EAX = `0x454E5242`, jump to `kernel_entry`.

**The protected-mode toggle** must leave 16-bit descriptors in the caches, because CS.D and SS.B survive clearing PE (Intel SDM vol. 3, section 9.9.2): `cli`; NMI off; recheck A20; PE on; far jump `0x08`; load `0x10`; `rep movsd`; load DS, ES, FS, GS, SS with `0x20`; far jump `0x18`; clear PE; far jump `0000:label`; reload real-mode segments; NMI on; `sti`.

**`BootInfo` at `0x500`:**

```text
0x00 u32 magic 0x454E5242   0x04 u32 region_count   0x08 u32 boot_drive
0x0C u16 com1_port          0x0E u16 crtc_port      0x10 u32 text_base   0x14 u32 conventional_kb
0x18 u16 columns            0x1A u16 rows           0x1C u32 reserved_count
0x20 u64 fb_base            0x28 u32 fb_pitch       0x2C u32 fb_width    0x30 u32 fb_height   0x34 u32 fb_format
0x38 reserved[8]: { u64 start, u64 bytes }             // 16 bytes each: page tables, stage 2, bounce buffer
0xB8 entries[32]: { u64 start, u64 bytes, u32 type }   // 20 bytes each, E820 shape
```

The same bytes on both widths; `os/none` reads them by fixed offset with `readUnaligned`, because `u64` alignment differs between `P == 4` and `P == 8`.

`os/none` presents a sanitised view, built at start into a `.bss` table. Real BIOS E820 tables can be unsorted or overlapping, so it sorts them and removes overlaps, with reserved winning. It marks as not `usable` everything below `0x10000`, the `reserved` ranges, the image and the stack. It clips usable regions at 4 GiB on `P == 4` and at the mapped limit on the long-mode BIOS path. So `heap.addBootRegions(boot)` is safe on a 640 KB machine with no E820, on a Q8400 board with RAM above 4 GiB, and with live page tables at `0x70000`.

**Error letters:** `C` CPU older than 386, `D` disk, `A` A20, `M` memory, `L` no long mode.

**`--base` validity.** `write_bios_image` reports EN1304 when `[base, bss_end)` overlaps `0-0xFFFF`, `0x10000-0x1FFFF` (unless `base == 0x10000`), `0x70000-0x75FFF` on long-mode images, or `0x80000-0xFFFFF`. `bss_end` includes the stack.

**Kernel start (`lib/os/none/start.en`, floor island).** A naked `_start`, in this fixed order, with no stack until step 3:
1. Remember whether EAX is `0x454E5242`. `rep stosd` over BSS inline, preserving EBX. If EAX did not match, point EBX at an empty `BootInfo` in `.bss`: no regions, no serial, text base `0xB8000`.
2. `lgdt` the image's own 3-entry GDT, far jump `0x08`, load segments with `0x10`. Nothing is assumed about the GDTR it arrived with.
3. Set ESP to `__stack_top` (default stack 16 KB in `.bss.stack`; `--stack-size`). Store the `BootInfo` pointer in a `.bss` word, which `vga.emergency` and `serial.kind` read; while it is zero they assume `0xB8000` and no serial. Set `__stack_limit`.
4. Install an early IDT: 32 entries pointing at `push imm8; jmp common` stubs (about 500 bytes of code, 256 bytes in BSS). Any CPU exception prints `CPU exception N` to VGA and COM1 and halts, rather than triple-faulting silently.
5. Detect the CPU, run `checkLevel`, set up FPU or SSE (section 8.3).
6. Call `@entry(&BootInfo)`.

**Devices.** VGA uses `text_base` with the cursor through the CRTC; no register programming, so MDA through VGA all work. Serial: zero base or LSR `0xFF` means absent; DLAB divisor 12 for 9600 8N1; `FCR 0xC7` then `IIR` bits distinguish 16550A (`11`) from buggy 16550 (`10`, FIFO left off) and 8250/16450 (`00`). Polling on LSR.THRE is bounded, so a missing port never hangs the kernel.

**USB on Core 2 boards.** Use `--image=hdd` on the Q8400. Writing is documented only (`TESTING.md` section 19). The toolchain never writes to raw devices, to avoid destroying a disk by accident.

### 9.7 `x86_64-none`, long mode, UEFI

**BIOS path.** Same stage 1 and image geometry, base `0x100000`, with `flags` bit 0 set. Stage 2's step 0 has already checked for long mode. It adds a tail after step 8:
1. Identity-map 4 GB with 2 MB pages at `0x70000`-`0x75FFF` (one PML4, one PDPT, four PDs: 24 KB), recorded in `BootInfo.reserved`.
2. Set CR4.PAE, then EFER.LME through `wrmsr`, then CR3, then CR0.PG.
3. Far jump through selector `0x28`.
4. Clear CR0.EM and set CR0.MP, CR4.OSFXSR and CR4.OSXMMEXCPT before any Enrang code runs, because SSE2 is the baseline but entering long mode does not enable it.

Interrupts stay on the 8259 PIC, which Core 2 boards provide. LAPIC, IOAPIC and SMP are deferred past M10.

**UEFI** (`--format=efi`). PE32+ with subsystem 10, mandatory `.reloc`, no import table; everything goes through `SystemTable`.
- Entry is `@abi("win64")`, `(image, systemTable)`.
- `__rt_start_efi` prints through `ConOut`, finds the framebuffer through `LocateProtocol` and GOP, calls `GetMemoryMap`, then `ExitBootServices` with map-key retry, and fills `BootInfo`, which lives in `.bss`, since `0x500` is not reserved under UEFI.
- Before `@entry` it does `cli`, loads its own GDT and IDT, and switches to `__stack_top`, so nothing runs on firmware tables.
- **Memory.** Only `EfiConventionalMemory` is usable. BootServices code and data stay unusable in the prototype, because the firmware's identity map stays active and its page tables, GDT and stack live there.
- **Output.** After exit, `text_base = 0`. `vga.Screen` and `vga.emergency` render with an 8x16 bitmap font when a framebuffer exists: at most 4 KB of rodata, tree-shaken, with glyphs drawn for this project because no third-party data is allowed. COM1 also works where it exists. Newer PCs typically have neither VGA text mode nor COM1, so without this a hello kernel and every panic would be invisible on the machines this path exists for.
- **Secure Boot** must be off, because the output is unsigned. The docs and the checklist say so.
- The output is one `.efi` file. Copy it to `\EFI\BOOT\BOOTX64.EFI` on a FAT stick; the prototype ships no FAT writer.

## 10. Runtime in Enrang

```text
lib/core/      prelude mem ptr int int64 float softfloat/{f32,f64,conv,rem,sqrt} fmt dragon4 string
               atomic cpu port option result panic trace rt_start   // `extend` and @intrinsic declarations live with their topic
lib/alloc/     prelude array string box heap into_iter
lib/os/        linux_x64/ linux_i386/ windows/ vm/ none/{start,bootinfo,vga,serial,idt,pic,pit} uefi/
lib/boot/      stage1 stage2_16 stage2_32 stage2_64
lib/conformance/ none_shim       // test-only console on COM1 so the corpus can run freestanding
```

**Embedding.** `enrang-rtlib`'s `build.rs` walks `lib/` and generates a sorted table of `(path, include_str!(...))`, so the binary needs no file at run time. `ENRANG_LIB_DIR` overrides the table for library development. There are no prebuilt objects: library code goes through the same front end as user code, lazily per reached function. `LibCache` shares parsed ASTs within a process, for `enrang test` and `enrang dev`.

**Layering.** `core` has no allocator and no OS; `alloc` needs a registered allocator; `os` is selected by `TargetSpec.os`. Dependencies point only downward, and the loader rejects a library import that violates this. `alloc`'s signatures are nevertheless visible on every target, so availability is enforced by EN0820 alone. Compiler-called functions are `@lang` items in a `define_lang_items!` table, including `__rt_alloc` and `__rt_dealloc`, the only allocation entry points, and `array_push` and `array_extend_cloned`, which `ArrayBuild` calls, with signature stubs by M3 and bodies at M4. A meta-test requires each to exist in every target's graph and to have a test.

**How built-ins are declared.** `string` is an `@lang("string")` class in `core/string`; `T[]` and `Box<T>` are `@lang` classes in `alloc`. `TyKind::{Str, Array, Boxed}` map to them through `Tcx::lang`. Methods on `T | null`, `*mut T`, the integers and the floats come from `extend` blocks. `lib/core` files are ordinary Enrang using `@intrinsic` for what cannot be written, and M2's `core signatures stub` is simply these declarations with bodies absent.

**Per target.**

| Target | Library | Heap source | Notes |
|---|---|---|---|
| `x86_64-linux` | `core alloc os/linux_x64` | `mmap` #9, chunks of at least 64 KB | `syscall` with `rax rdi rsi rdx r10 r8 r9`; clobbers `rcx`, `r11` |
| `x86_64-windows` | `core alloc os/windows` | `VirtualAlloc` | Referenced imports only |
| `i386-linux` | `core alloc os/linux_i386` | `brk` #45, falling back to old `mmap` #90 | `int 0x80`, at most 5 args since EBP is reserved; old `mmap` takes a pointer to six words; only SPEC 8.4's syscalls |
| `i386-none`, `x86_64-none` | `core os/none`, plus `alloc` if `@globalAllocator` | `heap.addRegion` from `BootInfo` | EN0820 without an allocator |
| UEFI | `core os/uefi` plus optional `alloc` | Same, after `ExitBootServices` | |
| VM | `core alloc os/vm` | `vm.alloc` host call | `DEV_RUNTIME.md` |

**Allocator.** `FreeListHeap` (SPEC 8.3): address-ordered first-fit with boundary-tag coalescing, 8-byte header on 32-bit and 16-byte on 64-bit, minimum block 16 and 32 bytes. Hosted heaps wrap it with a `grow` that adds regions, which coalesce when adjacent. Chosen over size classes because it needs no per-class pages and fits a 2 MB machine. In test builds, `alloc` adds two counters (`live_blocks`, `live_bytes`), read by the runner; production has none.

**Memory functions.** `core/mem` `copy`, `copyOverlapping` and `set` are `@intrinsic` declarations. The VM executes them with full provenance and bounds checks. Codegen lowers them to LIR `MemCopy` for small constant sizes, or `MemCopyDyn` and `MemSetDyn` otherwise: `rep movsd` then `rep movsb`, with a backward path for overlap that restores DF. So `T[]` growth and string `+` reach no `asm`, and the VM runs them. A meta-test forbids `asm` in `core` outside `core/port` and `core/cpu`; another requires, from M4, that the mono closure of S1-S8, S10 and S11 on VM rows contains no `Asm` statement.

**Size budgets**, enforced by failing tests from their milestone:

| Item | Limit | From |
|---|---|---|

## 11. Driver and CLI

One `enrang` binary. Exit codes: 0 success, 1 compile errors, failed tests or lost output, 2 usage, 3 internal compiler error (SPEC 13.2). Builds go to `out/`.

| Command | From | Behaviour |
|---|---|---|
| `enrang build [file]` | M5 | Native output. Default entry from `enrang.json` |
| `enrang run [file] [-- args]` | M4 (`--vm`), M5 native | Build and run on host. `x86_64-windows` runs through interop. Freestanding targets get EN1304 with the QEMU command to use |
| `enrang dev <file>` | M6 | `DEV_RUNTIME.md` |
| `enrang test [paths]` | M4 VM, M5 native | `TESTING.md` |
| `enrang check [file]` | M1, grows through M3 | Phases 1-5, no codegen; `ParseMode::Test`, so `.test.en` parts are checked; phase 5 only if a root exists |
| `enrang explain <code>` | M0 | Title, rule, failing and fixed examples, TS perspective; unknown code gets did-you-mean |
| `enrang init [name] [--kernel]` | M1 | Never overwrites (EN1307). `--kernel` at M9 |
| `enrang targets [--evidence]` | M0 | Targets, levels, aliases; `--evidence` prints the support ledger from `evidence/`, once the matrix driver generates it at M4; until then it prints a fixed table reading `planned` and `no hardware` |

**`enrang.json`:** `{"name":"hello","entry":"src/main.en","target":"x86_64-linux"}`, optionally `cpu`, `float`, `base`. `init` creates `enrang.json`, `src/main.en`, `src/main.test.en` with one passing test, and `.gitignore` containing `/out/`, anchored so it cannot match a source directory.

**Common flags (`build`, `run`, `check`, `test`):**

| Flag | Values |
|---|---|
| `--target=` | `x86_64-linux`, `x86_64-windows`, `i386-linux`, `i386-none`, `x86_64-none` (EN1303) |
| `--cpu=` | `i386`, `i486`, `i586`, `i686`, `sse2`, `x86-64`, plus SPEC 10.1 aliases |
| `--float=` | `soft`, `sse2`; `x87` is EN1020 |
| `--color=` | `auto`, `always`, `never` |
| `--error-format=` | `human`, `json` |

**Build flags:**

| Flag | Values | Notes |
|---|---|---|
| `-o <path>` | | EN1306 if not writable |
| `--format=` | `elf`, `pe`, `flat`, `efi` | Must fit the target, else EN1304 |
| `--image=` | `floppy`, `hdd` | Freestanding only |
| `--base=<addr>` | Hex or decimal | Flat and images; images reject overlaps with the boot stages (EN1304) |
| `--stack-size=<n>` | | Freestanding stack; PE reserve |
| `--no-stack-limit` | | Forfeits overflow soundness. Not a `TargetOpts` field: the driver clears `spec.stack.limit_check` after `resolve` |

VM rows are chosen by `--vm` and `--layout`, never by `--target`.

**`run --vm`** accepts `--layout=vm64|vm32`, `--float=soft`, `--allocator=enrang`, `--oracle`, `--max-memory=`, `--fuel=`. Grant flags and `enrang dev` flags are in `DEV_RUNTIME.md` section 4. Test flags are in `TESTING.md` section 4.

**Usage messages.** A malformed command line and a command that has not reached its milestone print an uncoded usage message and exit 2 (SPEC 13.1).

**Deferred commands** (`install`, `add`, `publish`, `doc`, `lsp`, `repl`, `bench`, `debug`, `upgrade`, `fmt`) are EN1301, exit 2, each with a golden. The deferred flags `--multiboot` and `--coverage` are EN1041. `tsc` and `lint` point to `check`, `compile` to `build`, `start` to `run` (EN1302). Anything else gets did-you-mean.

**Pipeline in `enrang-driver`:**

```text
resolve target -> load modules -> parse -> resolve+types -> [phase 2 stop]
-> mirbuild + borrowck per user body -> [phase 3 stop]
-> check_asm_levels, layout -> [phase 4 stop]
-> elaborate -> monomorphise (lazy library bodies) -> check_reachability -> [phase 5 stop]
-> VM: prepare + run
-> native: codegen -> link -> write
-> BIOS image: compile lib/boot stages with their own one-shot link, patch parameters, write image
```

## 13. Decisions that differ from the input proposals

SPEC.md wins everywhere. Where proposals conflicted with each other or with SPEC, this document chose as follows.

| Topic | Choice | Reason |
|---|---|---|
| Kernel load base | `0x10000` default per SPEC 7.8, with protected-mode bounce for high bases | Runs in 640 KB; no unreal mode |
| Allocator | Boundary-tag first-fit per SPEC 8.3, not size classes | Smaller on a 2 MB machine |
| Hard disk first bytes | `31 C0 EB 56`, no BPB | USB type-guessing evidence; floppy keeps a real-looking BPB |
| Segment order | RX with headers, then R, then RW | SPEC 7.8 section order; no file padding |
| x86-64 oracle name | `generic64`, not `nocona` | Measured here: `generic64` rejects `cmpxchg16b`, `lahf`, `sahf`, `popcnt`; `nocona` accepts `cmpxchg16b` |
| Allocator tiers | `none`, `linear` and `chaos` all at M5 | Hello ELF budget applies at M5, and chaos needs the agnostic emitter anyway |
| Jump tables | None | No data relocations in code; compare chains are enough for a prototype |
| Boot verification without QEMU | Add a test-only `x86sim` for 16- and 32-bit floor code with a scriptable BIOS and device models | Today nothing else can execute the boot path or the 386 detection branches |
| Soft-float timing | M8, then `--float=soft` in the VM | Keeps M4 small; the VM still gives a differential the moment the library exists |
| Multiboot | Deferred past M10 (EN1041) | Its 150 lines pay part of `enrang-sema`; disk images already cover the required boot path |
| Interrupt-safe allocation | Static EN0824, no run-time `cli` wrapper | A wrapper leaves panic-in-allocator re-entry open and spends the 2 KB budget |
| Owned iteration over `T[N]` | Copy elements only, EN1015 otherwise | A `FixedIntoIter<T, N>` lang class would need internal const generics for a rare case |
| Volatile and atomic width rules | Sealed bounds checked at the call | A bound is checked once, generically, so nothing new fires at mono |
| Type too large | One code, EN0435, at layout, mono and link | The check is one rule at three times |
| `for...of` over a path | No whole-loop loan; the source is read at every head and each element is an ordinary borrow | JS's visible pushes are the owner's decision, and the ordinary check still rejects a live element across a change |
| `for (const x of &queue)` | Means `for (const x of queue)`, not a frozen source | O8 makes `&` optional. A held reference freezes: `const r = &queue; for (const x of r)` |
| Spread of a `T[N]` | An ordinary MIR loop in mirbuild, not a raw-pointer library call | No `unsafe`, and no second lang item whose only caller is the compiler |
| Hidden loop index | `isize`, like `.length`, with a signed compare | One register on `i386`, and `_i < _n <= isize.MAX` holds once zero-sized `T[]` is limited at `isize.MAX` |
